# Rough候选结构优化：共享教师初始化与逐结构微调

这是历史Rough教师的独立BO流程，不是新3000结构、三任务专家的默认下一步。当前三任务直接看[快速启动](../docs/跨形态多任务共享策略训练流程.md#直接开训练)。

旧Rough源码已归档。推荐由 `start.py` 按检查点SHA恢复独立审计源码树，不能将档案目录直接作为运行目录。见[历史专家档案说明](../legacy/expert_sources_20261114/历史专家档案说明.md)。

## 优化协议

| 项目 | 设置 |
|---|---|
| 初始设计 | `ocd_mixed_design_50_full_cooling/ocd_design_50.csv` 中50个混合连续/类别设计 |
| 自适应搜索 | 默认再提出50个性能GPR＋可行性GPC候选 |
| 变量 | 大腿0.25–0.40m，小腿0.30–0.45m，膝3款×踝3款；不是新专家的5×6电机池 |
| 每个候选 | 同一机器人4096个副本，恰好微调200次PPO更新 |
| 初始化 | 每个候选使用相同actor、critic、归一化权重；Adam状态重新初始化，学习率从原检查点恢复为5.0625e−5 |
| 微调任务 | 固定10cm楼梯，前进指令0.5m/s，种子42，保留原Rough噪声和重置事件 |
| 评估 | 微调后确定性运行20秒；在可行设计中最小化完整轨迹前进速度MAE |

默认100个候选顺序运行，总计20000次候选PPO更新。摔倒或不足1000控制步判不可行，不填写完整时域MAE；运行异常、OOM或源码校验失败属于基础设施错误，停止并保留现场，不能当成结构不可行。

性能GP只使用成功完整轨迹，可行性GP使用全部有效成功/摔倒标签，采集函数为 `EI×P(可行)`。最终最佳设计必须实际成功，不能选不可行样本。

v2修正了旧实现遗漏控制步长、将完整轨迹误差放大50倍及混用失败尾项的问题。公式、旧数据只读转换及测试见[约束贝叶斯优化方法](约束贝叶斯优化方法.md)。旧六次零更新预试验只作历史记录，不混入当前200更新目标。

## 启动与恢复

服务器旧BO的独立一行入口，自动选择满足12.5GiB空闲显存、利用率不超过20%的卡：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/rough_bo/start.py
```

显式选卡时加 `--gpu 5`，仍要求12.5GiB空闲显存，但不使用自动选卡的利用率阈值。显存检查不是容量预留。

```bash
python rough_bo/start.py --check-only
```

上条检查输入、检查点/源码和选卡，不执行训练，但并非纯CPU提案预览。只看CPU提案应使用 `preview_proposal.py`。

旧BO恢复入口需要原输出目录；这是高级历史工作流，不属于三任务中文启动器：

```bash
python rough_bo/start.py --resume /absolute/path/to/bo_run --gpu 5
```

默认50个初始设计＋50个GP提案；`--bo-trials 0`仅做初始50个。恢复合同必须保持一致，若拒绝换卡须用原设备。只有审计文件真实移动时才显式指定 `--checkpoint`、`--bank` 或 `--code-root`，不能借此绕过身份。

Windows高级底层入口使用当前目录中的控制器：

```powershell
$run = Join-Path (Get-Location) ("run_" + (Get-Date -Format "yyyyMMdd_HHmmss"))
& "C:\Roboparty\env_isaaclab\Scripts\python.exe" .\bo_finetune_controller.py `
  --output $run `
  --bo-trials 50
```

## 源码恢复与运行记录

选卡前按检查点记录检查源码。三个已知编排文件 `train.py`、`train_stage.py`、`persistent_worker.py` 可用逐字节匹配的原件恢复；归档缺失文件也只按记录SHA恢复。其他未识别改动停止。审计源码树位于 `robolab/logs/rough_bo/source_snapshots`，原源码、数据和旧结果不被覆盖；不完整或被改动的缓存拒绝使用。

GPU编号对Torch、Kit渲染和PhysX保持一致；子环境清除可见卡掩码以使用物理编号。同用户已有BO进程或并发启动会被拒绝。

终端显示 `BO_PROGRESS 1/100`、PPO更新、评估及下一候选。Ctrl+C中断当前worker，日志仍保留。输出包含Optuna SQLite、`trials.csv`、`summary.json`、不可变 `run_contract.json`、候选请求、微调模型及各尝试日志。

该结果不是最终设计认证，最优候选还需重复种子和步态确认。
