# Rough约束贝叶斯优化：完整轨迹MAE与可行性建模

本页记录基于 `724b244` 的历史Rough BO v2协议。新三任务训练的结构范围、电机池和分组方法见[完整流程](../docs/完整流程.md)，不能把本页旧3×3电机池当成新专家设置。

本协议保留Kit文件监听修复、前台日志、GPU选卡、源码恢复及逐候选训练；不改变Isaac版本、冻结Rough源码、物理、奖励或旧结果。

## 1. 目标与可行性

每个候选从同一12000更新模型初始化，Adam重新建立，4096环境恰好微调200更新。评估使用1环境、种子42、前进0.5m/s、固定10cm楼梯、20秒和原确定性设置。

速度采用任务原生机体坐标系 `root_lin_vel_b[0,0]`，与同坐标系指令比较；不能与世界坐标位移/时间混用。

```text
# N=1000，控制步长dt=0.02秒。
MAE = sum(abs(vx[k] - command[k])) / N
    = sum(abs(vx[k] - command[k]) * dt) / 20
```

旧代码在观测误差求和时漏乘dt，却给摔倒后的尾项乘dt，导致完整轨迹放大50倍并扭曲排序。v2移除失败尾项，按完整轨迹平均。

摔倒或不足1000步为 `feasible=false`。部分轨迹误差只用于诊断；`objective_value` 与 `tracking_mae_fixed_horizon_mps` 为null。最终步正常时间截断属于完成，最终步摔倒仍不可行。新控制器要求 `metrics_schema=rough_complete_rollout_mae_v2`。

异常、OOM、源码审计失败、缺少summary属于基础设施错误：停止并保留尝试，不能输入GP当成结构失败。

## 2. 两个模型与混合变量

`constrained_gp.py` 使用CPU scikit-learn：

- 性能：GPR，只拟合成功完整轨迹MAE。模型内部标准化，报告仍是m/s；WhiteKernel描述小幅观测/建模噪声。
- 可行性：GPC，使用全部有效成功/摔倒标签，Bernoulli标签和logistic Laplace近似。
- 核函数：两个归一化腿长上的Matérn-5/2核，乘膝/踝电机身份上的指数Hamming核。电机只比较身份是否相同，不当成有序数值距离。
- 超参数按边际似然拟合，边界和优化警告写入提案审计。

选择最大 `EI(MAE)×P(可行)` 的提案。当前最优基准只能取实际观察到的可行候选。枚举9种电机组合，用扰动Sobol点和边界初始化连续搜索，再在原腿长范围内局部优化各组合的最佳点；排除已观察组合。采集函数优化是近似过程，不保证全局最大。

标签只有一类时，暂用Beta(1,1)后验概率，直到两类都有观察；还没有可行点时探索可行性和未访问区域。EI接近零时使用有明确记录的不确定性回退。可行概率是固定200更新协议下的模型估计，不是物理安全证明；一次摔倒不会永久屏蔽整类电机或整片区域。

Optuna只保存持久化数据库，自适应点均由上述采集函数显式入队，不使用RandomSampler选点。不可行试验为适配标量存储记录有限哨兵值 `1e6`；它不是测得MAE，不拟合性能GP，不能成为最佳候选。最终CSV和summary显式选择可行MAE，不依赖通用 `best_trial`；全不可行时最佳值为null。

模型库版本冻结在合同中；同版本恢复检查合同，已排队或运行候选保留原参数，失败尝试保留。

## 4. 只复用原始50个初始观察

旧v1的自适应点使用错误目标选择，不能直接 `--resume` 旧数据库。转换工具在旧run之外建立新JSON清单，原实验只读保留：

```bash
python rough_bo/repair_observations.py   --run /data/chenjiale/robo_cjl/robolab/logs/rough_bo/bo_20261030_185932_322114   --output /data/chenjiale/rough_bo_observations_v2.json
```

转换器检查合同、源码审计、检查点与bank身份、200更新预算、种子、评估设置及已知v1公式；从原观测MAE/采样时间恢复成功误差，失败样本保留标签而无目标，并记录旧分数及SHA。它不启动仿真、不加载模型、不重写数据库；缺失、歧义或不匹配时停止。

只导入试验0–49：46条成功目标和50个可行标签，其中4次摔倒。原自适应50–99不进入模型或最终排名，旧100点清单在加载时也会过滤。

明确要继续新训练时，用新run提出50个新候选：

```bash
python rough_bo/start.py   --observations /data/chenjiale/rough_bo_observations_v2.json   --bo-trials 50
```

可加 `--gpu 5`。导入点不重新训练；这里50指初始50点之外的50个新提案，进度从51/100到100/100。旧自适应搜索路径不沿用。实际检查点、bank、种子、LR及初始设计表仍需通过控制器审计。

仅在CPU上预览下一提案，不训练、不启动Isaac、不要求GPU：

```bash
python rough_bo/preview_proposal.py   --observations /data/chenjiale/rough_bo_observations_v2.json   --bank /data/chenjiale/robo_cjl/robolab/logs/rough_hybrid/dynamic_20261026_174456/bank/bank.json   --output /data/chenjiale/rough_bo_next_proposal.json
```

预览的可行性和MAE是预测，不是新的实测结果。预览检查清单和bank，实际执行前还由控制器审计基础模型与源码。

## 5. 测试与容量设置

```bash
python -m pytest rough_bo/tests -q
```

回归覆盖50倍误差、早期/最终步摔倒、缺失/非有限数据、旧版本拒绝、类别置换不变性、核梯度、真实GPC区分能力、仅失败观察更新、提案唯一与复现、单类回退、不可行点排除、幂等热启动导入，以及控制器/worker参数/前台日志/源码恢复。

BO场景构建前，将 `cfg.sim.physx.gpu_total_aggregate_pairs_capacity` 至少设为 `2**23`（8388608），已有更大值保留。这是 `totalAggregatePairsCapacity` 溢出对应的宽相位缓冲区，独立于接触/patch上限。各worker保存 `physx_capacity.json`。

该设置增加GPU容量需求，不改变4096环境、奖励、地形、电机、步长、碰撞过滤或PPO。只影响新构建场景；CPU测试不能证明服务器实际溢出已消除。合同绑定改动源码，应用时使用初始50点清单建立新run，不能悄悄续接旧合同，也不反向认证旧结果没有警告。

## 6. 方法依据

- [Gardner等，ICML 2014，Bayesian Optimization with Inequality Constraints](https://proceedings.mlr.press/v32/gardner14.html)：目标/约束分开建模，用可行概率加权EI。
- [Gelbart等，UAI 2014，Bayesian Optimization with Unknown Constraints](https://arxiv.org/abs/1403.5607)：未知约束的概率处理。
- [scikit-learn高斯过程文档](https://scikit-learn.org/stable/modules/gaussian_process.html)：回归和logistic Laplace分类后端。

本实现采用二元可行性分类，不伪造连续安全裕量，不声称逐项复现上述论文全部设置。代码修复验证不包含新的长训练。
