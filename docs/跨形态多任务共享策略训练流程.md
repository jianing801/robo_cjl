# 跨形态多任务共享策略训练流程

更新：2026-11-25。本项目比较机器人结构、执行器和控制器适应后的实际性能。三个跨形态专家提供冻结教师，共享 Actor 提供统一初始化，每个候选独立微调并实测，再由连续 BO 选择结构。

## 完整流程

| 阶段 | 操作与产物 |
|---|---|
| 1. 结构库 | 10 档大腿×10 档小腿×5 款膝电机×5 款踝电机，共 2500 结构；绑定三个任务的真实资产、物性和 AMP 参考动作 |
| 2. 专家训练 | 分别训练 Rough 上楼、负重和 AMP 跑步，保存冻结教师检查点及原生配置 |
| 3. 共享蒸馏与选模 | 在 400 个结构采集 BC/DAgger 标签；用固定 200 个结构和三个种子闭环选模，获选第 5 轮共享 Actor |
| 4. 初始 BO 观测 | 按[新版原生 PPO 微调](共享策略原生PPO微调说明.md)对原第 21 组的 50 个结构各做 100 次方案 B 联合 PPO 更新（4096 环境），固定工况独立评估；同算法已测数据可复用 |
| 5. 原机定标 | 先用[原机 B 第100次更新重新实测](三任务BO评估与结构搜索.md)，三任务各四指标形成十二项固定分母。旧 V4 基准只作历史对照，不与 B 混用 |
| 6. 连续 BO | 前 50 个观测初始化 GP；第 51–100 个候选腿长连续搜索，膝踝各五款可选。新结构生成对应 URDF、USD、AMP 参考动作；微调/评估预算和前 50 个一致 |

2500 格点只是专家训练的有限样本，BO 在大腿 0.20–0.40 m、小腿 0.25–0.45 m 内连续优化。共享策略的选模成功率、微调过程的 Mean reward 和正式 BO 的硬件代价是不同的量，不相互替代。[五轮选模结果](共享策略五轮选模记录.md) · [原机实测基准](原始配置基准.md)

## 直接开训练

已有 `robo_cjl` 和 `amp_hhtools` 环境、已切到仓库根目录时：

```bash
conda run --no-capture-output -n robo_cjl python start.py rough --gpu 0
conda run --no-capture-output -n robo_cjl python start.py 负重 --gpu 0
conda run --no-capture-output -n robo_cjl python start.py amp --gpu 0
conda run --no-capture-output -n robo_cjl python start.py 蒸馏 --gpu 0
```

使用一次性迁移后的旧结构库时，每条命令加 `--migrated`。多个专家可分别使用不同卡；同一张卡不重复启动。蒸馏后续追加轮、选模和冻结 Actor 见[共享策略蒸馏详细说明](共享策略蒸馏详细说明.md)。已完成的模型可以直接复用。

下一步直接按[三任务 BO 评估与结构搜索](三任务BO评估与结构搜索.md)的三个步骤执行：准备或复用前 50 个观测、用原机冻结评分、开始连续搜索。正式搜索不需要重新训练专家和共享学生。已有同协议的 50 份实测报告，只需要重新计分。

人工暂停后在对应的原命令上加 `--resume-paused`。每个阶段沿用其原输出、协议及源码身份，普通故障时补跑未完成部分；恢复不能用另一份模型、修改清单或直接删除暂停标记来绕过。

## 工程准备与输出索引
