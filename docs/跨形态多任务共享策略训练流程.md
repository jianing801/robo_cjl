# 跨形态多任务共享策略训练流程

**本页仅用于跨形态多任务共享策略流程，不涉及普通固定形态或单任务训练。**

启动直接复制下面的命令，先分别训练跨形态专家，再蒸馏成共享策略。 适用于你的服务器 `/data/chenjiale/robo_cjl`，已有 `robo_cjl` 和 `amp_hhtools` 环境。

## 没有完整空闲卡时：先转换三个任务的USD

分任务、分卡、暂停恢复和进度解释集中在[USD资产准备启动说明](USD资产准备启动说明.md)，可直接复制命令。

指定5号卡，按Rough→负重→AMP顺序准备，复制一行即可：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 资产 --gpu 5
```

**只转换仿真资产，不启动PPO，也不要求AMP参考动作先完成。** 一次只运行一个任务的转换器，全部完成后退出。默认选全部三个任务；只准备Rough时，在末尾加 `--任务 rough`。

转换的最低空闲显存检查为4GiB，与训练的12.5GiB分开；这只是启动阈值，不是显存峰值保证。你目前10GB空闲显存可以尝试，OOM会保留日志并停止，不结束别人的进程。

已有Rough训练目录时，会校验复用它已成功的转换资产；尚未创建训练计划的任务，缓存在本实验的 `资产准备/任务名/`，不制造“有缓存却没plan”的专家目录。完整缓存路径写入 `启动记录/任务名_asset_cache.json`。之后直接执行下面的训练命令，入口自动传递该缓存，不需要手工复制路径。

中断后再执行同一条资产命令；成功任务校验复用，失败任务保留现场并继续处理剩余结构。任一任务失败则停止，不跳过失败继续报“全部完成”。有用户暂停标记、同库活跃转换器或训练进程时会停止。此处不做跨任务缓存共享。

如果上一次是你按Ctrl+C暂停的，明确继续时在资产命令末尾加 `--resume-paused`。程序只对尚未启动PPO的转换暂停保存审计并恢复，不会取消已有PPO训练的暂停。

协调器不加载Isaac、Carb、Omni或USD原生组件，启动后会打印 `CACHE_PHASE COORDINATOR_PYTHON_ONLY`；只有真正导出结构的worker加载原生运行时。协调器健康轮询不会每分钟打印Timeout线程栈；worker的原生诊断仍保留。该隔离用于降低协调器受原生库影响的风险，不代表已证明任何SIGSEGV根因消除。

转换前的结构库校验、网格哈希和旧缓存复用也会输出阶段。父进程每10秒打印 `CACHE_HEARTBEAT`，Linux会显示子进程状态及最近阶段/计数；`disk-sleep` 表示等待磁盘，不能仅凭出现该状态就判定整个进程45分钟都卡在同一个文件。`CACHE_REUSE_PROGRESS`显示已复用数量；正常日志不再逐文件打印路径。

可捕获异常和中断会写失败/退出记录，并在终端显示错误详情。stderr每60秒的线程栈是诊断信息，不等于已判失败。父子进程被强制杀死或底层存储失联时，任何程序都不能保证日志落盘；本入口不宣称修复磁盘硬件或共享存储故障。

全部完成会打印 `USD_ASSETS_ALL_SELECTED_READY`。它仅表示USD准备好，不表示专家或策略已经训练成功。要运行PPO仍需满足下面的训练显存条件。

## 直接开训练

**Rough专家，0号卡：**

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 0
```

**负重专家，0号卡：**

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 负重 --gpu 0
```

**AMP专家，0号卡：**

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py amp --gpu 0
```

**换卡只改最后的数字；中断后再次执行同一条命令，就是续训。** 不用激活环境，不用设置ENTRY/ROOT/OUT，不用复制结构库或时间戳目录，不用自己加 `--resume`。

同一张卡不要同时开三个任务。选卡仍要求至少12.5GiB空闲显存并通过启动锁检查；条件不满足就停止，不会结束别人的任务。

### 程序会自动处理什么

- 三个结构库都已存在就复用；尚未建立则先准备结构库。
- 优先使用本入口记下的目录；兼容之前手动启动的同bank时间戳目录，找到计划就续训。
- 无计划的空壳目录保留并换新目录；有文件但缺少计划则停止，避免误从头训练。
- AMP已有完整参考动作就严格校验复用，没有就先生成。
- 先准备仿真资产，再训练；转换默认持续运行，逐结构保存，异常时只处理剩余结构。
- 旧版转换阶段计划由审计工具自动判断能否迁移；已经开始PPO后不绕过源码身份。
- 达到任务原定预算后验收完成记录，不额外增加训练。

部分生成的结构库/参考目录、用户暂停标记、无有效检查点的初始失败或身份不匹配仍会停止，并保留现场。

### 查看进度

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 状态
```

该命令只查看运行目录及完成记录，不把“有计划”当成“进程还活着”。实际进程互斥和检查点检查由训练控制器负责。

| 屏幕信息 | 含义 |
|---|---|
| `NATIVE_CACHE_PROGRESS 24 / 3000` | 正在准备仿真资产，尚未开始PPO |
| `CACHE_SESSION_INTERRUPTED` | 转换异常或停滞，保留成功资产后恢复剩余结构 |
| `Learning iteration` | 正在做PPO更新 |
| `STAGE_COMMITTED` | 当前结构组已保存，即将换组；不是整个任务完成 |
| 专家 `completed.json` | 达到预算，仍需模型身份与步态验收 |

终端复制通常用 **Ctrl+Shift+C**；Ctrl+C会中断任务。

## 完整流程

顺序只有四步：**匹配结构库 → 三个专家分别训练 → 蒸馏与配对评估 → 查看三任务单机器人录像。** 已完成的步骤直接跳过。

### 1. 可选：提前做准备

日常直接用上面的训练命令即可。只有想在空闲时间先完成准备，才单独执行：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 准备
```

没有空闲卡时，提前用CPU生成AMP参考动作：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 参考动作 --cpu
```

有空闲卡时，参考动作可用GPU；与上条只选一条：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 参考动作 --gpu 0
```

参考动作是AMP使用的运动序列；仿真资产是URDF转换成的USD，两者不同。已有完整参考库不重做。首次机器尚未部署Isaac、HHTools或原始机器人资产时，才查阅[环境与资产准备](环境与资产准备.md)，入口不会自动升级依赖。

### 2. 分别训练三个专家

直接使用本文最上面的三个命令。三个任务有各自的形态条件教师模型，此时尚不是一个共享策略。

### 3. 三个专家完成后，一行蒸馏

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 蒸馏 --gpu 0
```

自动定位三个教师，验证预算、检查点、源码/结构身份及AMP参考库，建立共同结构计划；执行行为克隆及3轮DAgger，再自动进行三个任务的全库教师/学生配对评估。再次执行同一条命令按原计划恢复。

默认每批10种结构，采样1000步、每5步保存，拟合20个epoch。教师参数冻结，不训练共享PPO critic。已有共享计划若绑定其他教师会拒绝替换。

执行结束不等于步态通过：查看 `shared_policy/completed.json` 的 `nominal_passed`，要求三个任务分别通过。没通过就保留真实结果，不自动增加预算，不用MSE或平均reward冒充成功。

### 4. 看三个任务的单机器人视频

共享蒸馏执行完成后，分别复制：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 录像 --任务 rough --gpu 0
```

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 录像 --任务 负重 --gpu 0
```

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 录像 --任务 amp --gpu 0
```

默认录库内第0个结构，只显示一个机器人；负重为10kg。终端打印录像输出目录。想换结构，在命令末尾加 `--结构 100`，无需复制设计ID；编号从0开始。

录像用于直观看步态，不能替代全库评估。基本标准：完整20秒、不摔、前进速度至少0.1m/s；楼梯还需上升至少0.1m，忽略横移。库外新结构须先准备对应运动学和AMP参考，不能直接换个ID使用。

## 训练配置

| 项目 | 正式设置 |
|---|---|
| 结构库 | 大腿10档 × 小腿10档 × 膝5款 × 踝6款＝3000种 |
| 大腿/小腿范围 | 0.20–0.40m / 0.25–0.45m，各10档，允许已授权GP外推 |
| 空间并行 | 4096环境，每组60种，每种68或69份 |
| 时间轮换 | 每组50次PPO更新，50组覆盖一轮，合计2500更新 |
| Rough/负重预算 | 各12000更新，完整4轮＋第5轮40组 |
| AMP预算 | 5000更新，完整2轮 |
| 原生形态条件 | 29维，类别编号按全库固定 |

膝5款：RS04、DM-J10010L-2EC、DM-J10010-2EC、DM-J6248P-2EC、DM-J10422P-2EC。

踝6款：RS06、DM-J4340P-2EC、DM-J8009P-2EC-V1.1、DM-J4340P-2EC-V1.1-48V、DM-J8006-2EC-V1.1、DM-J6216P-2EC；不含4310P。普通4340P与V1.1-48V参数不同。其余固定腿部用10010L，肩与臂用普通4340P。

全身23关节使用各电机真实扭矩—转速硬包络，软惩罚为：

```text
-12 × 控制步长 × sum(max(abs(实际输出扭矩)/动态可用扭矩 - 0.8, 0)^2)
```

步长只乘一次，旧六关节软惩罚关闭。动态可用力矩接近零时，该关节从此项中排除并单独统计，不做除零；非有限数据不伪装成零成本。此项不额外惩罚超速。

Rough与AMP基础结构匹配；负重另有背包体，0.30kg是模板初始化质量，运行时由原负载课程覆盖，不重复叠加。负重课程按绝对更新0–999、1000–2999、3000+推进，换组不重新暖身。

AMP教师保留原生三帧按项排列观测及归一化器；共享学生使用十帧流式适配。新运动学必须有匹配参考，不按近似腿长猜测。

正式组表固定：每组30种电机组合各2次，每档大腿、小腿各6次；轮间仅旋转组内顺序以分散额外副本，训练中不重新搜索组表。按之前要求，算法、真实搭配及理论依据单独保留在[结构分组轮换训练方法](结构分组轮换训练方法.md)。

### USD检查进度与GPU占用

训练启动先在CPU上校验首组60个结构，通过后才申请GPU；换组只校验当前组的结构和源网格依赖。全库完成证明仍须覆盖3000个设计，但不再在每组解析全库URDF。每次校验中每个资产文件只读一次，保留SHA256完整性检查。

独立“资产”操作发现完整缓存时先校验，不要求空闲GPU。新转换或旧资产恢复完成后，协调器已经验证的资产不在外层再全量读一遍；外层交叉确认本次完成报告和缓存完成报告、结构覆盖及bank身份，然后登记。历史缓存仍需校验，不能把历史报告当成永远有效。

输出说明：`CACHE_VALIDATE_SOURCE_MESHES`表示所需结构数量；`CACHE_URDF_PROGRESS`与`CACHE_MESH_PROGRESS`显示结构源文件和网格检查进度；`CACHE_VALIDATE_PROGRESS 12 / 60`为已通过数；等待超过10秒会出现`CACHE_VALIDATE_WAIT`，正常日志不逐文件打印路径。`CACHE_FINALIZED`为本次子进程完成报告核对成功，`USD_ASSETS_READY`才表示独立资产操作已登记结束。存储本身发生阻塞时仍可能慢，不能用心跳替代成功证据。


### 正式训练的USD快检（与单独资产准备分开）

Rough、负重、AMP专家的正式训练默认使用`TRAIN_CACHE_FAST_PROGRESS 已完成 / 当前组数量`。已完成缓存的USD不再逐层重算内容SHA256。保留完整证明的bank身份及全库覆盖检查、当前组结构/转换身份、小型URDF和配置哈希，以及文件存在、非空、大小、修改时间和inode检查。首先检查当前组，再申请GPU；场景建立前也使用快检。元数据变化会停止并要求完整审计，不会自动转入耗时的全库重建。

缓存下`.training_fast_checks/`保存分组元数据基线。旧缓存首次接入时信任已有完整转换证明并建立当前元数据基线，**不是重新证明旧USD当前字节仍等于原哈希**；快检不等同内容完整性审计。之后会拒绝已记录元数据的变化，增加场景硬链接不会误报。源码、物理、结构库和检查点身份验证仍保留，模型、优化器、奖励与曲线没有改变。已进入PPO的冻结训练链不自动更换源码身份。

仅修改正式专家训练路径；单独`start.py 资产`继续使用原有完整校验，评估/零更新smoke也保留默认深检。USD真正加载进仿真仍需要读取，快检不消除引擎初始化耗时。

在服务器真实首组60结构上实测，首检0.155秒、重复0.163秒，测试中禁止了USD内容读取。该结果是当时文件系统状态下的缓存检查耗时，不是冷缓存保证或整个训练启动时间。
