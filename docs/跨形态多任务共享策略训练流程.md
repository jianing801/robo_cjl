## 完整流程

| 阶段 | 做什么 | 核心产物与边界 |
|---|---|---|
| 1. 匹配结构库 | 按腿长、膝踝电机的完整参数键匹配三个任务 | 2500结构正式库、任务映射、USD；AMP另需匹配运动学的参考库 |
| 2. 三个专家 | 分别训练楼梯/粗糙地形、负重行走和AMP跑步形态条件策略 | 三个冻结教师及其原生配置，不是一个共享控制器 |
| 3. 共享蒸馏 | BC＋3轮DAgger，使用任务条件和形态条件训练同一学生 | 在 400 种结构上采集，3 个候选学生在同一批 200 个结构上与教师配对比较（参与蒸馏采集和未参与的结构各 100 个） |
| 4. 候选微调 | 指定真实库内结构；三个任务共同更新该候选专属actor | 鲁棒PPO、完整学习状态检查点；固定预算不保证获得理论最优控制 |
| 5. 候选独立评价 | 单独微调后可做名义和鲁棒步态诊断。正式 BO 微调后直接进入固定工况评估 | 独立诊断保存 `candidate_result.json`。正式 BO 保存 `bo_evaluation.json` |
| 6. BO与最终验证 | 用原机的实测指标归一化，复用前 50 个初始观测，按联合可行性和加权代价搜索后 50 个结构 | `bo_evaluation.json`、冻结的原机基准与权重、`observation.json`、搜索预算报告 |

三任务 BO 通过 `multitask_morphology/bo.py` 启动。首次准备时用 `initialize --measure-only` 微调并评估原第 21 组的 50 个结构，已有同协议的完整测量可直接复用。用 `freeze-scoring --original-rpo-reference` 冻结原机的九项分母和评分权重，再用 `search` 自动提议、微调和测量后 50 个候选。每个结构从同一份胜出共享模型出发，用单进程 4096 环境和普通 PPO 随机回合计时做 100 次联合更新，随后按固定种子运行三个任务各一条正式试次。总体和分任务 Mean reward 保存在候选的 `tuning/mean_reward.csv`。任一任务在正式试次中失败，该结构失去最终排名资格。[三任务 BO 评估与结构搜索](三任务BO评估与结构搜索.md)

## 直接开训练

已有 `robo_cjl` 和 `amp_hhtools` 环境时，在服务器依次执行；同一张卡一次训练一个任务，卡号按需修改：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 0
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 负重 --gpu 0
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py amp --gpu 0
```

三个专家完成后：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 蒸馏 --gpu 0
```

蒸馏结束后可以准备 BO 的 50 个初始结构，也可以单独指定候选。两种入口默认都微调 100 代，`真实结构ID` 从共同结构表读取。[三任务 BO 说明](三任务BO评估与结构搜索.md) · [查询候选结构 ID](候选结构微调与续训.md#候选选择和启动)

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 微调 --gpu 0 --candidate-task stairs --candidate-design-id 真实结构ID
```

普通报错后重复相同命令会定位原目录；人工暂停后加 `--resume-paused`。专家首组无完整提交、蒸馏未完成拟合、候选PPO中断的恢复方式不同，分别查对应文档，不手动删暂停标记混用。

## 关键配置与当前边界

正式专家采用大腿10档×小腿10档×膝5款×踝5款，共2500结构；4096环境分组轮换。共享部分目前只包含持续上楼梯、负重行走和跑步，不包含主动停步验收。楼梯仍为三档高度×两档踏步深度；蒸馏保留既定采样频率与预算。

共享学生是候选控制器的初始化。蒸馏师生差值用于检查能力是否丢失；候选结构最终的优劣应基于专属微调后的独立表现。CPU回归通过不等于Isaac Lab仿真通过，也不等于受扰恢复或实机部署已经验证。

## 输出索引

默认实验根目录为 `robolab/logs/multitask_full2500_physical/`。

首次执行准备、资产或训练命令可从头建立新版结构库。要从旧 3000 结构库筛出 2500 个并独立保存，使用 `start.py 迁移 --gpu 5`。完成后该库位于 `robolab/logs/multitask_full2500_physical_migrated/`，后续操作加 `--migrated`。[两种资产准备方式](USD资产准备启动说明.md)

三个专家的 Actor、Critic 和蒸馏后的共享 Actor 使用同一套 28 维物理条件。旧 2500 结构版也是 28 维，但各列的意义不同，需在原实验路径用原代码续训。新版从自己的初始权重开始。

| 目录 | 读取入口 |
|---|---|
| `banks/`、`references/`、`资产准备/` | 结构、AMP参考和资产准备证明 |
| `启动记录/`、`experts/` | 专家实际运行目录、预算与完成记录 |
| `shared_plan/` | 三教师检查点身份及共同结构映射 |
| `shared_policy/` | `selection.json`、`completed.json`及数据/评估索引 |
| `candidate_finetuning/<结构键摘要>/` | `manifest.json`、`checkpoints/`、`candidate_result.json`、`completed.json` |
| `bo/` | 固定工况原始测量、配对结果、候选提议、BO 观测及每个完成预算的报告 |
| `videos/` | 共享学生录像，属于观察材料，不能替代统计评估 |

代码统一入口为 [start.py](../start.py)，核心目录为 [multitask_morphology](../robolab/experiments/multitask_morphology/)。更细的函数和文件索引位于蒸馏、微调两份说明末尾。
