# 专家训练与运行操作

更新：2026-11-18。返回[文档索引](README.md) · [总训练框架](跨形态多任务共享策略训练流程.md)。以下适用于服务器 `/data/chenjiale/robo_cjl` 的已有conda环境。

## 没有完整空闲卡时：先转换三个任务的USD

分任务、分卡、暂停恢复和进度解释集中在[USD资产准备启动说明](USD资产准备启动说明.md)，可直接复制命令。

指定5号卡，按Rough→负重→AMP顺序准备，复制一行即可：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 资产 --gpu 5
```

**只转换仿真资产，不启动PPO，也不要求AMP参考动作先完成。** 一次只运行一个任务的转换器，全部完成后退出。默认选全部三个任务；只准备Rough时，在末尾加 `--任务 rough`。

转换的最低空闲显存检查为4GiB，与训练的12.5GiB分开；这只是启动阈值，不是显存峰值保证。你目前10GB空闲显存可以尝试，OOM会保留日志并停止，不结束别人的进程。

已有Rough训练目录时，会校验复用它已成功的转换资产；尚未创建训练计划的任务，缓存在本实验的 `资产准备/任务名/`，不制造“有缓存却没plan”的专家目录。完整缓存路径写入 `启动记录/任务名_asset_cache.json`。之后直接执行下面的训练命令，入口自动传递该缓存，不需要手工复制路径。

中断后再执行同一条资产命令；成功任务校验复用，失败任务保留现场并继续处理剩余结构。任一任务失败则停止，不跳过失败继续报“全部完成”。有用户暂停标记、同库活跃转换器或训练进程时会停止。此处不做跨任务缓存共享。

如果上一次是你按Ctrl+C暂停的，明确继续时在资产命令末尾加 `--resume-paused`。程序只对尚未启动PPO的转换暂停保存审计并恢复，不会取消已有PPO训练的暂停。

协调器不加载Isaac、Carb、Omni或USD原生组件，启动后会打印 `CACHE_PHASE COORDINATOR_PYTHON_ONLY`；只有真正导出结构的worker加载原生运行时。协调器健康轮询不会每分钟打印Timeout线程栈；worker的原生诊断仍保留。该隔离用于降低协调器受原生库影响的风险，不代表已证明任何SIGSEGV根因消除。

转换前的结构库校验、网格哈希和旧缓存复用也会输出阶段。父进程每10秒打印 `CACHE_HEARTBEAT`，Linux会显示子进程状态及最近阶段/计数；`disk-sleep` 表示等待磁盘，不能仅凭出现该状态就判定整个进程45分钟都卡在同一个文件。`CACHE_REUSE_PROGRESS`显示已复用数量；正常日志不再逐文件打印路径。

可捕获异常和中断会写失败/退出记录，并在终端显示错误详情。stderr每60秒的线程栈是诊断信息，不等于已判失败。父子进程被强制杀死或底层存储失联时，任何程序都不能保证日志落盘；本入口不宣称修复磁盘硬件或共享存储故障。

全部完成会打印 `USD_ASSETS_ALL_SELECTED_READY`。它仅表示USD准备好，不表示专家或策略已经训练成功。要运行PPO仍需满足下面的训练显存条件。

## 暂停后恢复：仍然只用统一入口

正常启动只需任务和卡号，例如4号卡：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 4
```

**首组中断、没有检查点时，明确重新开始首组：**

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 4 --restart-initial
```

只在明确要重新开始首组时加该选项。入口自动寻找原bank和完整USD缓存、核对配置与预算、创建新目录并记住新目录；旧目录、日志和旧暂停标记保留。已经有检查点/提交或同库活跃进程时拒绝重开，避免丢弃训练成果。缺少完整USD证明时停止，不在恢复时重新转换。后续继续使用上面的普通启动命令，不用填写ROOT、ENTRY、USD或训练目录。

**已有正式提交断点，明确解除暂停并续训：**

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 4 --resume-paused
```

该选项保存恢复审计后解除当前任务的暂停标记；首组已中断但没有提交断点时会要求使用`--restart-initial`，不把重新初始化伪装为续训。无恢复选项时始终尊重USER_PAUSED，不自动恢复。两项选项不能同时使用。负重和AMP使用相同选项，只替换任务名称。实际训练仍执行原有源身份和检查点校验，不改写已有模型身份。


**负重专家，0号卡：**

```bash

```

**AMP专家，0号卡：**

```bash

```

**换卡只改最后的数字；中断后再次执行同一条命令，就是续训。** 不用激活环境，不用设置ENTRY/ROOT/OUT，不用复制结构库或时间戳目录，不用自己加 `--resume`。

同一张卡不要同时开三个任务。选卡仍要求至少12.5GiB空闲显存并通过启动锁检查；条件不满足就停止，不会结束别人的任务。

### 程序会自动处理什么

- 三个结构库都已存在就复用；尚未建立则先准备结构库。
- 优先使用本入口记下的目录；兼容之前手动启动的同bank时间戳目录，找到计划就续训。
- 无计划的空壳目录保留并换新目录；有文件但缺少计划则停止，避免误从头训练。
- AMP已有完整参考动作就严格校验复用，没有就先生成。
- 先准备仿真资产，再训练；转换默认持续运行，逐结构保存，异常时只处理剩余结构。
- 旧版转换阶段计划由审计工具自动判断能否迁移；已经开始PPO后不绕过源码身份。
- 达到任务原定预算后验收完成记录，不额外增加训练。

部分生成的结构库/参考目录、用户暂停标记、无有效检查点的初始失败或身份不匹配仍会停止，并保留现场。

### 查看进度

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 状态
```

该命令只查看运行目录及完成记录，不把“有计划”当成“进程还活着”。实际进程互斥和检查点检查由训练控制器负责。

| 屏幕信息 | 含义 |
|---|---|
| `NATIVE_CACHE_PROGRESS 24 / 2500` | 正在准备仿真资产，尚未开始PPO |
| `CACHE_SESSION_INTERRUPTED` | 转换异常或停滞，保留成功资产后恢复剩余结构 |
| `Learning iteration` | 正在做PPO更新 |
| `STAGE_COMMITTED` | 当前结构组已保存，即将换组；不是整个任务完成 |
| 专家 `completed.json` | 达到预算，仍需模型身份与步态验收 |

终端复制通常用 **Ctrl+Shift+C**；Ctrl+C会中断任务。

## 训练配置

| 项目 | 正式设置 |
|---|---|
| 结构库 | 大腿10档 × 小腿10档 × 膝5款 × 踝5款＝2500种 |
| 大腿/小腿范围 | 0.20–0.40m / 0.25–0.45m，各10档，允许已授权GP外推 |
| 空间并行 | 4096环境，每组50种，每种81或82份 |
| 时间轮换 | 每组50次PPO更新，50组覆盖一轮，合计2500更新 |
| Rough/负重预算 | 各12000更新，完整4轮＋第5轮40组 |
| AMP预算 | 5000更新，完整2轮 |
| 原生形态条件 | Actor 和 Critic 同用 28 维物理量，版本为 `leg_motor_inertia_v1` |

膝5款：RS04、DM-J10010L-2EC、DM-J10010-2EC、DM-J6248P-2EC、DM-J10422P-2EC。

踝5款：RS06、DM-J4340P-2EC、DM-J8009P-2EC-V1.1、DM-J4340P-2EC-V1.1-48V、DM-J6216P-2EC；不含8006和4310P。普通4340P与V1.1-48V参数不同。其余固定腿部用10010L，肩与臂用普通4340P。

全身23关节使用各电机真实扭矩—转速硬包络，软惩罚为：

```text
-12 × 控制步长 × sum(max(abs(实际输出扭矩)/动态可用扭矩 - 0.8, 0)^2)
```

步长只乘一次，旧六关节软惩罚关闭。动态可用力矩接近零时，该关节从此项中排除并单独统计，不做除零；非有限数据不伪装成零成本。此项不额外惩罚超速。

Rough与AMP基础结构匹配；负重另有背包体，0.30kg是模板初始化质量，运行时由原负载课程覆盖，不重复叠加。负重课程按绝对更新0–999、1000–2999、3000+推进，换组不重新暖身。

AMP教师保留原生三帧按项排列观测及归一化器；共享学生使用十帧流式适配。新运动学必须有匹配参考，不按近似腿长猜测。

正式组表固定。每组 25 种电机组合各 2 次，大腿、小腿各档均为 5 次。轮间旋转组内顺序，分散额外环境副本。[结构分组轮换训练方法](结构分组轮换训练方法.md)

## 形态输入

形态条件按下表顺序拼接。惯量张量以各腿段质心为参考点，用各自的连杆坐标轴表示。腿段数据取自该结构的实际 URDF，利用左右对称性只取左侧。

| 列 | 内容 |
|---|---|
| 1–2 | 大腿、小腿长度 |
| 3–5、6–8 | 膝、踝分别提供峰值扭矩、关节侧最高转速、关节侧等效惯量 |
| 9–18、19–28 | 大腿、小腿分别提供质量、质心三坐标，以及惯量的 `Ixx Iyy Izz Ixy Ixz Iyz` |

每列采用冻结结构库的最小值和最大值缩放到 `[-1, 1]`，常量列取 0。仿真仍使用全身真实扭矩曲线和权重 −12 的全身扭矩软惩罚。

### USD检查进度与GPU占用

训练启动先在CPU上校验首组50个结构，通过后才申请GPU；换组只校验当前组的结构和源网格依赖。全库完成证明仍须覆盖2500个设计，但不再在每组解析全库URDF。每次校验中每个资产文件只读一次，保留SHA256完整性检查。

独立“资产”操作发现完整缓存时先校验，不要求空闲GPU。新转换或旧资产恢复完成后，协调器已经验证的资产不在外层再全量读一遍；外层交叉确认本次完成报告和缓存完成报告、结构覆盖及bank身份，然后登记。历史缓存仍需校验，不能把历史报告当成永远有效。

输出说明：`CACHE_VALIDATE_SOURCE_MESHES`表示所需结构数量；`CACHE_URDF_PROGRESS`与`CACHE_MESH_PROGRESS`显示结构源文件和网格检查进度；`CACHE_VALIDATE_PROGRESS 12 / 50`为已通过数；等待超过10秒会出现`CACHE_VALIDATE_WAIT`，正常日志不逐文件打印路径。`CACHE_FINALIZED`为本次子进程完成报告核对成功，`USD_ASSETS_READY`才表示独立资产操作已登记结束。存储本身发生阻塞时仍可能慢，不能用心跳替代成功证据。


### 正式训练的USD快检（与单独资产准备分开）

Rough、负重、AMP专家的正式训练默认使用`TRAIN_CACHE_FAST_PROGRESS 已完成 / 当前组数量`。已完成缓存的USD不再逐层重算内容SHA256。保留完整证明的bank身份及全库覆盖检查、当前组结构/转换身份、小型URDF和配置哈希，以及文件存在、非空、大小、修改时间和inode检查。首先检查当前组，再申请GPU；场景建立前也使用快检。元数据变化会停止并要求完整审计，不会自动转入耗时的全库重建。

缓存下`.training_fast_checks/`保存分组元数据基线。旧缓存首次接入时信任已有完整转换证明并建立当前元数据基线，**不是重新证明旧USD当前字节仍等于原哈希**；快检不等同内容完整性审计。之后会拒绝已记录元数据的变化，增加场景硬链接不会误报。源码、物理、结构库和检查点身份验证仍保留，模型、优化器、奖励与曲线没有改变。已进入PPO的冻结训练链不自动更换源码身份。

仅修改正式专家训练路径；单独`start.py 资产`继续使用原有完整校验，评估/零更新smoke也保留默认深检。USD真正加载进仿真仍需要读取，快检不消除引擎初始化耗时。

在服务器真实首组60结构上实测，首检0.155秒、重复0.163秒，测试中禁止了USD内容读取。该结果是当时文件系统状态下的缓存检查耗时，不是冷缓存保证或整个训练启动时间。


## 三个专家任务的总时长

通过`start.py rough`、`start.py 负重`、`start.py amp`启动时自动计时，不增加命令参数。从进入start.py开始，包含结构库准备、身份检查、GPU检查、参考动作准备、仿真加载和训练，到正式completed.json写出为止；不包含调用Python之前conda自身启动的开销。计时观察进程不操作GPU或训练，不改变原有exec、暂停、检查点和源身份规则。

累计训练用时每满一小时显示一次 `TASK_TIMER 任务 累计训练用时 HH:MM:SS`。结束或中断时，`TASK_TIMER_FINISHED` 显示状态和累计训练用时。

训练目录的 `timing.json` 保存累计用时，`accumulated_run_hms` 为可读值。入口会打印持久副本的位置。同一训练目录续训会接上上次累计，暂停和断开至下次启动之间的时间从统计中排除。重开首组的新训练目录单独计时。

暂停、报错、未完成不会被标成训练完成；完成需预算匹配且存在非空最终检查点，步态是否通过仍另行评估。计时约每30秒落盘；正常结束保存最终值，进程退出检测约1秒精度。整机断电或强杀计时观察进程可能只留下最后一次落盘记录，不能凭该记录冒称完整精确用时。

新增计时只对更新后经统一入口启动的进程生效，不会自动接管已在运行的旧进程，也不能补算历史已退出的启动次数。如果已有训练提交而此前没有计时记录，结果会标记`history_before_timer_unknown=true`，只表示已记录时段，不当作完整历史训练成本。


### 首组中断但已经保存模型

首组内的模型文件与完整组提交是两类证据。没有完成任何组时，可明确从第0代重新开始：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py rough --gpu 3 --restart-initial
```

GPU编号按需要替换。该选项新建训练目录，保留旧目录、所有组内模型和暂停标记；不会把组内模型当成已完成组，也不会声称接着该模型继续训练。若已有完整组提交，应使用 `--resume-paused`，保留已提交进度。普通启动仍不自动解除暂停。

任务计时从统一入口启动开始，包含当次准备和加载。暂停后从训练目录记录的累计用时继续，停机间隔不计入。


### 不同任务并行与旧断点兼容

控制器仅拦截同bank、同训练目录或归属不明的仿真worker；其他任务可在不同GPU并行。2026-11-17的修复提供严格限定的旧断点兼容：只有控制器进程检查及对应兼容逻辑这两处审阅修改可通过，反向还原后必须符合原源码SHA，其他源码、bank、配置、物理和模型身份仍严格比较。旧策略和Adam身份不重新绑定，兼容审计保存在训练目录的 `controller_scope_compatibility.json`。


### 训练进程内源文件校验复用（2026-11-17）

不改变启动命令。正式训练生成和复核实验身份时，首次解析全库URDF并完整哈希共享网格；同一进程下次遇到同一源集合，如果URDF及网格的大小、修改时间、元数据变更时间、设备和文件标识均未改变，则复用已经验证的网格哈希，显示 `TRAIN_SOURCE_CACHE_HIT 2500 / 2500`。源文件变化会失效并完整复核，缺失直接报错。进程重启后重新完整检查，不把磁盘旧记录当作永久可信证明。

该优化减少重复读取，不缩短PhysX原生初始化本身；结构库本身的其他物理、GP和URDF校验仍执行。元数据复核不等于每次密码学内容复验，刻意保持元数据的内容修改不能据此保证检出。手动 `mesh_sources(bank,use_cache=False)` 和默认调用仍完整读取；独立USD转换和 `validate_cache` 默认深检不变。

本机3000结构可行性测试中重复完整读取约20秒。正式实现首次完整校验含依赖稳定性检查约44.81秒，后续三次元数据复核约0.213、0.220、0.206秒，返回的24个网格哈希完全一致。首次冷启动可能更慢，收益来自同一进程后续换组的重复复核。实际服务器收益取决于磁盘缓存及其他校验占比，不保证换组总时间同比缩短。18环境原生测试仍约10秒，候选第三组原生USD导出停滞尚未解决；本次不改变清理、PhysX、传感器或现场转换流程。
