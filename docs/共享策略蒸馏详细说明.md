## 启动与整体顺序

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 蒸馏 --gpu 0
```

自动定位三个教师，验证预算、检查点、源码/结构身份及AMP参考库，建立共同结构计划。先检查教师，再执行行为克隆及3轮DAgger；每轮保留多个epoch候选，先在6个共同物理结构上初筛，再让前两名进入12个结构、3个种子的扩大验证。最后对选中的学生进行三个任务的全库教师/学生配对测试。普通报错后可复用已提交结果；人工暂停使用 `--resume-paused`，详见本文“暂停恢复与记录兼容”。

默认每批10种结构，采样1000步、每5步保存，拟合20个epoch。教师参数冻结，不训练共享PPO critic。已有共享计划若绑定其他教师会拒绝替换。

默认使用 `robust` 采集协议：三个任务分别继承自己的原生物理随机化，学生使用带噪观测，教师保留原生输入语义与冻结归一化器。速度、楼梯和负载按工况采样；随机化参数真值只用于仿真和记录，不额外作为学生输入。任务、结构、关节、动作缩放和控制节拍仍执行一致性检查。

按用户最新范围，共享策略只训练和评价持续负重行走、上楼梯及跑步。`shared_randomization_v2`在三个任务的BC/DAgger采集、教师参照、学生选模、最终测试和共享PPO微调中均关闭随机站立指令；运动速度仍在各自范围内重采样。原生专家训练配置和已有教师权重不改写。本版本不以主动停步或原地站稳为训练、验收目标。

楼梯的 `robust` BC/DAgger采集为每个结构至少12个环境：六种台阶高度/宽度组合各有独立训练、验证副本，并实际设置地形列及出生点。新计划的楼梯闭环评估与PPO沿用每结构8份，每个结构覆盖六种组合；8份对六档的数量为[2,2,1,1,1,1]，并非六档等权。其他任务按计划的副本数执行。环境划分用于动作拟合验证，跨轮闭环选模另行运行，不复用训练轨迹。

首轮BC的随机化强度默认为0.25，三轮DAgger依次为0.5、0.75、1.0。这个系数用于逐渐增加扰动，不代表将名义质量或PD参数直接乘以该系数；乘性参数围绕1收缩，延迟保持合法整数档。只有BC而不做DAgger时，直接使用目标强度。采样范围是待教师预检的训练设计，不保证每种结构都能完成最高负载、最高速度和最难楼梯的组合。

`teacher_preflight.json` 保存代表性场景的教师存活、命令跟踪成功率与前向速度RMSE。默认复用12个结构、3个种子的教师扩大验证；教师某个结构或整个任务的观测成功率为零，也保留结果继续蒸馏，不按教师表现划分可用/不可用结构。身份、样本覆盖和数值等数据完整性错误仍会停止流程。此报告不保证教师在整个采样分布内可靠。

`selection_round_*.json` 记录每轮的epoch初筛与晋级，`selection.json` 记录跨轮选择。所有同阶段候选和教师使用相同结构、种子及目标随机化强度，逐任务、逐结构比较成功率差值。所有结构都采用相同公式，不设教师“好/坏”分界；退步与提升分别汇总，防止某些结构的提升抵消另一些结构的损失。选模先最小化最差任务的平均成功率损失，再比较三任务平均损失、学生绝对成功率、存活时长、测量完整性及速度RMSE。任务间等权，任务内结构等权。结构子集优先覆盖电机类别和腿长端点，再补充分散结构，仍不构成未见结构泛化证明。最终测试使用独立种子，不反向参与选模。

同种子比较用于配对场景及初始随机条件，学生传感噪声使用独立随机数流。动作不同或摔倒触发不同重置后，原生环境的随机数消耗可能分叉，因此不宣称整个轨迹中每次命令、外推扰动都逐时刻完全相同。

全库最终测试默认分别运行两套协议：`nominal` 保留旧固定工况作为回归基准，`robust` 检查带随机化工况。查看 `completed.json.profile_results` 中各协议的师生独立指标及 `teacher_comparison`，逐任务、逐结构检查能力损失。`policy_all_episodes_command_tracking_passed` 分别描述教师和学生是否所有已测回合均通过，不再作为蒸馏成功的总开关。完成结果明确标记仍需候选结构微调；共享策略的测试不能替代微调后评价、完整楼梯通过或实机验收。

需要调整时，可以在统一命令后追加 `--randomization-strength 0.5 --initial-randomization-strength 0.25`；`--collection-profile nominal` 用于旧固定采集条件的消融，最终评估仍默认同时运行两套协议。`--evaluation-profile nominal` 或 `robust` 可以明确选择单套最终测试，未运行的另一套不会报告通过。

采集、验证协议及源码身份绑定到运行记录。旧版无协议的 `shared_policy/manifest.json`，或不同协议/预算的已有目录，不能直接续写新数据；程序保留旧结果并明确拒绝。需要新协议时，使用底层入口指定新的输出目录，仍复用原来的三教师计划：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/robolab/experiments/multitask_morphology/distill.py --plan /data/chenjiale/robo_cjl/robolab/logs/multitask_full2500_physical_v1/shared_plan/plan.json --output /data/chenjiale/robo_cjl/robolab/logs/multitask_full2500_physical_v1/shared_policy_motion_v2 --device cuda:0 --batch-designs 10 --collect-steps 1000 --stride 5 --epochs 20 --dagger-rounds 3 --timeout-seconds 1800
```

这个高级命令的结果位于新输出目录；统一录像入口仍读取默认的 `shared_policy/completed.json`，不会自动替换旧模型。

## 1. 学生是什么、输入输出是什么

三个跨形态专家分别提供楼梯、负重行走和跑步标签；所有标签用于训练同一个任务与结构条件化的共享学生。当前三任务 `pipeline.py` 显式采用 `SharedMLPActor`：隐藏层为 **1024、512、256**，激活为 ELU，输出23个关节动作。此网络结构沿用已有三任务实现，本次没有更换架构。

| 项目 | 当前实现 |
|---|---|
| 动态观测 | 每帧78维：机身角速度3、投影重力3、速度命令3、关节位置偏差23、关节速度偏差23、上一执行动作23 |
| 学生历史 | 10帧，按时间从旧到新排列，共780维；回合开始用首帧填满历史 |
| 任务条件 | 楼梯、负重、跑步的3维 one-hot；一次推理指定一个任务 |
| 结构条件 | 直接使用三个专家共用的 28 维物理量，包括腿长、膝踝出力和速度上限、旋转等效惯量，以及大腿和小腿的质量、质心与惯量张量 |
| 图结构数据 | 规范数据中仍携带350维图特征用于结构校验；当前 MLP 的 `features()` 不把这350维送入网络，因此不能据此宣称学生使用了图网络 |
| 输出语义 | 23维未缩放关节位置动作；名义目标为默认关节位置加 `0.25 × action`，后续由任务执行器处理 |
| 控制周期 | 0.02秒，即50 Hz；这是策略控制频率，不等于物理子步频率 |
| 数值边界 | 学生观测和执行动作统一截断到 ±100；这是数值保护值，不能当作实机安全关节限位 |
| 不额外提供的量 | 随机质量、实际背包质量、摩擦系数、随机PD增益、质心偏移、延迟档位等仿真真值 |

统一的是学生可解释的输入输出接口，包括关节顺序、默认姿态、单位和尺度、历史布局、动作缩放、控制节拍与数值边界。各教师自身的历史和已训练归一化方式保持原生语义：直接任务保留其原生历史，AMP教师仍使用3帧原生历史及冻结归一化器；AMP学生单独建立10帧历史。

这里必须区分三件事：**学生观测接口统一、教师保留原生输入、学生噪声分布是否一致**。前两项已经实现；第三项是训练分布的设计选择，不是共享网络要求必须相同的接口条件。本版角速度噪声幅值为楼梯/负重0.20、跑步0.35，其他已列学生传感噪声幅值相同。这种差别本身不构成代码错误，也不能将本版代码概括成“三个任务的所有观测设置都完全统一”。任务速度范围不同会改变命令数值，但不会改变命令在观测中的字段、单位和位置。

## 2. 教师与学生怎样看到同一个环境

每个采集环境只维护一套实际机器人状态，物理随机化同时作用于教师标注和学生控制所在的世界。为它建立两个观测通道：教师使用干净的原生观测，学生使用加入传感噪声的统一历史。教师参数冻结，生成当前状态对应的动作标签；学生学习从带噪输入预测该标签。

| 阶段 | 实际执行谁的动作 | 学生训练输入 | 监督目标 |
|---|---|---|---|
| 首轮BC采集 | 对应任务的教师 | 同一物理状态的带噪10帧历史、任务、结构 | 冻结教师的动作，按共同动作边界处理 |
| 后续DAgger采集 | 上一轮学生 | 学生当时实际使用的带噪输入 | 教师对学生走到的状态重新给出的动作 |
| 学生闭环评估 | 被评估的学生 | 当前评估协议对应的观测 | 记录运动结果，不用教师动作替换学生动作 |

DAgger保存的输入与执行学生动作时的输入相同。它补充学生自身误差导致的状态分布；速度、地形和负载范围仍必须由环境采样显式覆盖。

噪声只加到每一帧新进入的传感数据，历史旧帧保留原来的噪声；某个环境结束回合后，仅清除该环境的历史。噪声采用独立随机数生成器，避免因额外生成学生噪声直接改变环境的随机数流。命令、上一动作、任务编号、名义结构信息不加噪。

满强度 `robust` 的噪声为逐分量均匀分布 `U(-a, a)`，下表给出幅值 `a`；课程强度为 `s` 时幅值乘以 `s`。

| 观测通道 | 楼梯 | 负重 | 跑步 |
|---|---:|---:|---:|
| 机身角速度（rad/s） | 0.20 | 0.20 | 0.35 |
| 投影重力 | 0.05 | 0.05 | 0.05 |
| 关节位置偏差（rad） | 0.03 | 0.03 | 0.03 |
| 关节速度偏差（rad/s） | 1.75 | 1.75 | 1.75 |

这些是当前工程配置，并非论文规定的通用最优噪声值；能否满足具体实机传感器误差，仍需结合部署条件判断。

同一套传感硬件可以采用共同的基础误差模型，也可以在训练中额外混合多个噪声等级。按任务设置不同噪声是一种鲁棒性训练假设，并不证明实机跑步时误差一定比行走更大；当前0.20/0.35没有被本次工作标定为实测传感器误差。是否统一数值应根据部署需求与对照评估决定，不能仅因为三个教师配置不同就推断这些差别必须保留，也不必为了形式一致强制改成同一值。

相关方法依据：[Miki等，Science Robotics 2022，Learning robust perceptive locomotion for quadrupedal robots in the wild](https://arxiv.org/abs/2201.08117)，正文“Student policy training / Height sample randomization”和补充材料S8在同一学生训练中使用多种高程观测噪声条件，并随课程增加噪声强度。这支持“一个学生可以训练于多个噪声分布”的设计思路；该实验针对外感知高程观测，不能直接作为本项目IMU噪声取0.20或0.35的数值依据。

## 3. 三个任务各自的采样分布

默认 `robust` 并非把三个专家的所有随机化上下界合并。每个任务从自己的原生配置复制后设置采集协议，保留对应的材料摩擦与恢复系数、质量、质心、执行器增益、关节参数、推扰和动作延迟配置。原生某个参数上下界相等时，继承后仍是固定值；“启用该事件”不代表所有字段都产生变化。实际范围和执行状态以每次运行的 `randomization_audit.json`、`physics_audit.json` 为准。

| 工况 | 楼梯 | 负重行走 | 跑步 |
|---|---|---|---|
| 前向命令范围 | 0.2–0.6 m/s | 0.2–0.8 m/s | 1.5–2.5 m/s |
| 横向命令 | 0 | 0 | 0 |
| 目标航向 | 0 rad | −0.3–0.3 rad | −0.3–0.3 rad |
| 随机站立指令 | 关闭（0%） | 关闭（0%） | 关闭（0%） |
| 命令重采样间隔 | 8–10秒 | 8–10秒 | 8–10秒 |
| 主要环境条件 | 台阶高0.05/0.075/0.10 m，宽0.25/0.35 m，共6组 | 背包质量在0.1–5、5–10、10–15 kg三档内连续采样 | 保留跑步任务原生场景及AMP参考对应关系 |

三个任务都采用航向控制，角速度命令受 ±0.4 rad/s 范围约束；不是另外独立随机采样任意转弯速度。楼梯初始偏航使用 `±0.15 × s` rad，其余初态按任务原生范围缩放。

**教师楼梯地形与当前蒸馏地形并不完全相同。** 原始`ROUGH_TERRAINS_CFG`的台阶高度范围为0.05–0.15 m；本项目教师入口`engine/hybrid_runtime.py::configure_rough`将楼梯子地形覆盖为0.05–0.10 m，踏步深度仍为0.25、0.35 m两种。这里的`step_width`指每级台阶沿行进方向的踏步深度，不是整段楼梯的横向通行宽度。教师地形图为10行×20列，楼梯包含正、倒金字塔两种形式，另混合斜坡、粗糙地面、平地等子地形。

教师高度不是固定的5、7.5、10 cm三点：按[Isaac Lab 2.3.2地形生成规则](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/api/lab/isaaclab.terrains.html#terrain-generator)，10个难度层分别在各自的难度区间内采样，再将难度线性映射到5–10 cm高度范围，相当于5–5.5、5.5–6、……、9.5–10 cm的分层采样。每个地形块生成后，其台阶几何固定；环境重置时根据运动距离更新所在难度层，不是每个回合重新连续抽取并重建楼梯，也不是每一级踏步都独立随机高度。

当前蒸馏的三档高度×两档深度是采集协议的简化，便于均衡分配和记录工况，不是Isaac Lab或蒸馏算法的必要限制。采集器使用一行六列的固定倒金字塔楼梯，并禁用了按表现升降地形层的逻辑；其`curriculum=True`用于固定列类型分配，不能据此声称蒸馏沿用了教师的地形课程。若改成区间采样，可预生成有限的分层随机地形池，保留准确几何记录及独立验证样本。高度恢复5–10 cm区间取值属于恢复教师配置中的高度覆盖；深度改成25–35 cm连续采样则会加入教师配置没有直接提供的中间深度，需要同时记录教师和学生在这些条件下的表现。本段仅说明差别，未修改现有六组采集配置，也不证明具体教师检查点已经掌握配置内的所有地形。

负载在创建采集环境时抽样，同一环境本次采集中保持该载荷；相邻训练和验证副本在同一质量档独立抽样。背包惯量尺寸比例满强度为0.9–1.1，安装面偏移上限为(0.005, 0.005) m，质心偏移上限为(0.015, 0.010, 0.020) m；实际属性写入 `payload_audit.json`。

目前速度范围是任务级显式范围，**尚未实现依据腿长、台阶高宽或背包质量动态降低速度上限**。以上范围需要教师预检和后续闭环结果支持，不能把抽到了某个工况写成已经学会该工况。

`nominal` 则用于固定条件回归：楼梯/负重速度0.5 m/s、跑步速度2 m/s；楼梯为0.1 m高、0.25 m宽；负重默认0.3/5/10/15 kg；关闭学生噪声、startup/interval随机化与延迟。保留受限初态采样，因而不能将“nominal”解释为所有状态完全无随机性。

<a id="section-5"></a>

### 3.1 蒸馏、评估与微调中的随机化边界

BC数据采集属于学生训练的数据生成环节。教师权重冻结、使用推理模式，只表示教师不再学习，不代表仿真环境必须确定，也不代表整个环节是独立测试。离线拟合时只读取数据并更新学生；环境随机化主要在生成这些数据的仿真采集阶段生效。DAgger则让学生执行动作，再由冻结教师对学生实际访问的状态提供标签。

需分别理解以下设置：

| 设置 | 当前蒸馏采集中的处理 | 含义 |
|---|---|---|
| 质量、摩擦、增益等物理参数及外部推扰 | `robust`按任务原生配置和课程强度作用于同一个环境 | 教师和学生对应同一个实际物理状态，不是各自抽取一个不同的世界 |
| 学生观测噪声 | 在统一学生观测通道中添加 | 学生学习用带噪传感输入预测教师动作 |
| 教师原生观测噪声 | 关闭 | 教师看到的是受扰动后的干净状态，不是未受扰动的理想轨迹；不额外向原生输入添加特权字段 |
| 教师动作探索 | `act_inference`输出确定性动作 | 不将随机探索动作作为监督标签；执行器延迟与物理扰动仍可存在 |
| 参数更新 | 教师不更新，学生在拟合阶段更新 | 冻结教师不等于冻结整个学习流程 |

例如机器人被推歪后，教师根据真实的倾斜状态给出动作，学生根据同一状态的带噪观测学习该动作。干净教师输入能减少标签中额外的传感噪声，但不保证教师动作最优，也不保证学生一定能够从有限历史中恢复全部隐藏信息。

**评估同样可以保留随机化。** 名义条件测试回答固定工况能否完成，鲁棒性测试回答参数、传感和扰动变化后表现如何。评估时冻结策略和归一化统计，固定测试分布与种子列表，对不同检查点使用相同协议；最终测试与训练、选模数据分离。当前各轮选模使用相同的目标强度，最终分别报告`nominal`和`robust`。注意这两个配置还改变速度、地形、负载等采样分布，因此它们的差值不能解释成单独开启噪声或推扰的因果效果。

原论文中的具体做法：

- [Miki等，Science Robotics 2022](https://arxiv.org/html/2201.08117v1)，正文“Domain randomization / Student policy training”和补充材料S3：学生沿用教师训练环境，额外对学生高程观测加噪；学生训练开始时不加高程噪声，随后在蒸馏期间逐渐增加。该方法支持“干净教师监督、带噪学生输入、渐进课程”的设计，但研究对象是高程感知，不能据此认定本项目各传感通道的具体噪声幅值最优。
- [Agarwal等，CoRL 2022，Legged Locomotion in Challenging Terrains using Egocentric Vision](https://proceedings.mlr.press/v205/agarwal23a/agarwal23a.pdf)，第3节`Noisy`对照方法：教师使用无噪高程图，蒸馏学生使用带噪高程图，两个训练阶段都模拟40 ms延迟。这里的40 ms与大噪声设置属于该对照方法，不是所有主方法的统一配置，也不是本项目应照搬的数值。

“干净蒸馏→带随机化、观测噪声和扰动的PPO微调”也是可研究的训练安排，并非原则性错误。对本项目而言，它可能使有限预算的每结构微调承担更多补学鲁棒性的工作，并影响有限预算下的结构比较；这只是需要验证的风险，不是已证明的结果。任何安排都不能仅凭随机化开关宣称解决了sim-to-real，结论应来自最终控制器的测试和实机结果。

若比较两种安排，应保持任务、结构、命令、地形、负载覆盖与训练预算一致，仅改变BC/DAgger阶段是否加入物理随机化、传感噪声、推扰及延迟；两组使用同一套后续鲁棒PPO和独立评估协议。主要比较相同微调预算后的性能和达到目标性能所需的微调步数，而不是只比较蒸馏动作MSE。不要直接将现有`nominal`与`robust`作为此对照的两个训练组，因为它们还包含上述工况分布差异。当前保留渐进鲁棒蒸馏配置，本次说明不构成新的实验结果。

## 4. 随机化课程、数据平衡与拟合

统一入口的默认顺序是：教师预检 → BC → DAgger 1 → DAgger 2 → DAgger 3。四轮强度依次为0.25、0.50、0.75、1.00。每轮都保留前面轮次的数据，后续拟合从上一轮选出的学生权重开始；每次调用拟合器会新建 Adam，未跨轮恢复优化器状态。

这里的“上一轮学生”现在指上一轮扩大闭环验证选出的检查点；下一轮DAgger用它执行采集并初始化拟合。动作MSE仅作诊断，不再提前淘汰候选。跨轮最后再用相同扩大验证指标比较各轮赢家。统一入口显式设置3轮DAgger；直接调用底层 `pipeline.py` / `distill.py` 的默认值仍是0轮，需按实验意图显式设置。

强度影响随机化幅值，不缩小本节规定的速度、台阶或负载采样范围，也不改变推扰的原生触发频率。加性扰动围绕0缩放，乘性扰动围绕1收缩，材料摩擦围绕1收缩；执行器延迟按原生整数端点缩放并四舍五入。延迟的单位是执行器缓冲步，不能直接按0.02秒换算。

| 项目 | 统一入口默认值及实际含义 |
|---|---|
| 每个采集作业 | 10种结构、1000个控制步；每5步保存一行，约20秒 |
| 拟合轮数 | 每次BC或DAgger拟合20个epoch |
| 监督损失 | 默认动作MSE；默认任务和关节损失权重均为1 |
| 拟合优化器 | Adam，学习率0.0003，梯度范数上限1；学生默认保留原生观测尺度，不另拟合经验归一化 |
| 每次优化批次 | 每任务128行，三个任务合计384行；每任务抽8个结构项，每项抽16行，均允许有放回采样 |
| 结构及来源平衡 | 各任务等量，任务内均匀抽结构，再均匀抽该结构的来源数据分片 |
| 训练数据保留 | 所有原始训练分区行均可被抽取，不再固定截成32行；通过mmap按需读取，默认缓存2个archive |
| 训练行采样 | 结构、来源确定后，均匀抽工况，再抽环境/episode，再抽其中一行；有放回抽样，每次重新抽取 |
| 工况编号 | 速度分为3档前进速度，编号0/1/2，不再含站立档；楼梯还区分6种台阶，负重还区分3档质量 |
| 动作误差验证数据 | 与训练使用不同物理环境流；每结构/来源固定分层选最多128行，分块遍历这些行，不是全部holdout行 |
| 每epoch优化预算 | 默认按每结构/来源最多32次期望抽样计算步数，取最大任务预算除以128向上取整；与可访问数据量分离，可显式指定步数 |
| 实际覆盖记录 | 每轮拟合逐epoch累计记录抽样次数、不同训练行数及占全部可访问训练行的比例；跨拟合轮不合并此计数 |

这里的32现在是计算量起点，**不是固定保留的32条数据**。此前原始采集文件也已保存，问题在于拟合只使用固定小子集；现在训练分区中的行全部具有被抽到的机会。同一结构在不同epoch可以抽到不同轨迹，但“可访问”不等于“已经访问”或“已经学会”。mmap避免一次性复制全部观测，索引和覆盖位图仍占内存，系统文件缓存也不受两个archive这个数值硬限制。

**保存频率与控制／观测历史频率必须分开。** 当前控制和10帧学生历史都每0.02秒更新一次（50 Hz），教师也逐控制步提供动作；`stride=5`仅使监督样本每0.10秒保存一次（10 Hz）。每条监督样本包含当时的10帧连续历史以及当前教师动作，不能描述成“观测每0.10秒才更新一次”。两次保存之间的状态可能仍在后续历史输入中，但未保存时刻的教师动作并没有因此成为独立监督目标。例如，若关键纠偏发生在0.12–0.18秒之间，0.10和0.20秒的样本可能都没有直接标注最关键的纠偏时刻；这只是解释采样机制的例子，不是已观察到的真实失败轨迹。重置还会清理历史，历史输入不能保证保存所有中间状态。

以每结构12个楼梯副本、其中6个训练副本和6个独立验证副本为例：每次采集1000个控制步，每副本保存200行，故每结构／来源有1200条训练行。当前这1200行全部可抽样；在各任务结构数与来源数相同、每个分区至少32行的默认预算下，每epoch每结构／来源平均预计抽取32次，20个epoch约640次。这里是期望抽取次数，不是640条不同数据，更不是每个结构都获得精确相同次数。代码中的epoch由优化预算定义，不代表把全库数据遍历一遍。后续DAgger重新使用历史来源，会提供额外访问机会，但不能保证每条样本都已训练。

分层采样先平衡任务，再随机选结构、来源、工况、环境／episode和时间行；同一行允许重复。当前工况区分速度、楼梯规格或负载档位，没有专门的“恢复动作”标记，因而不能保证短暂恢复标签得到优先训练。覆盖记录按任务汇总可用行数、抽取总次数、不同训练行数和比例，范围是单次拟合内逐epoch累计，不能将它解释成恢复片段专属覆盖率或四轮合并覆盖率。分析最终选中模型时应读取其对应epoch的记录，而非默认把最后epoch的覆盖当作所选模型的覆盖。即使所有行都抽到，也仍须用闭环受扰恢复表现判断控制能力。

## 5. 多时间点候选、分级闭环选模与最后测试

每个epoch都保存权重及动作验证误差。默认20个epoch中，第5、10、15、20个epoch进入闭环评估；候选由时间间隔选取，不按动作MSE预筛。拟合器保留兼容字段 `summary.student` 指向MSE最低者，但主流程以 `checkpoints` 和闭环结果选模型，不把此兼容字段当作本轮赢家。文件和JSON中的epoch编号从0开始，对应4、9、14、19。

先让所有候选在6个共同结构、同一随机种子上初筛，取前两名在12个共同结构、3个种子上扩大验证。初筛结构是扩大集的子集，种子默认20261117、20261119、20261120。两阶段均使用目标随机化强度，而不是各轮较低的采集强度；教师按相同场景评估。各轮赢家按同一扩大集比较，最终选出共享学生。每次比较都保存逐结构的教师参照差值，取消 `matches_teacher_on_each_selection_task` 作为结论；保存相对最好的模型不代表所有结构都达到教师水平或适合实机部署。

对任务 $t$、结构 $d$，以相同协议、种子集合及评估副本数得到教师成功率 $p^T_{t,d}$ 和学生成功率 $p^S_{t,d}$，统一记录：

$$
\Delta_{t,d}=p^S_{t,d}-p^T_{t,d},\qquad
L_{t,d}=\max(p^T_{t,d}-p^S_{t,d},0),\qquad
G_{t,d}=\max(p^S_{t,d}-p^T_{t,d},0).
$$

这里零仅表示师生结果相等，不是教师能力好坏的分界。教师90%到学生70%、教师30%到学生10%，均是损失20个百分点；教师、学生都为10%，则该成功率指标没有观测到损失。教师成功率为零仍使用同一公式，不作分组，不除以教师成功率。所有结构都保留学生和教师的绝对指标；不把“与较弱教师相当”解释为绝对控制能力合格。

先在每个任务内对 $L$ 按结构取平均，再优先最小化三个任务中最大的平均损失，其次最小化三任务平均损失。提升 $G$ 和有符号差值 $\Delta$ 另行报告，不能抵消损失。随后按等任务、等结构权重比较学生绝对成功率、存活比例、测量完整性和速度RMSE，完全相同时保留较早检查点。仅排序值保留12位小数，避免浮点尾差阻止理论相同的损失进入后续比较，原始差值报告不舍入；这属于数值精度处理。该排序是本项目以保留教师能力为目标的工程选择，不是文献证明的最优排序，也没有新增“低于多少损失才算蒸馏合格”的门槛。

成功率仍受单回合成功条件影响，且有限回合下只能取离散比例；因此同时保存每结构存活时长比例差、速度RMSE差、有效测量比例和两方样本数。零成功率差不能证明其他控制行为一致，小差值也不能自动称为统计显著。师生结构集合、判据、各结构的种子/协议及副本数必须一致，否则拒绝比较；不把摔倒后已分叉的随机轨迹称为逐时刻配对。教师和学生都弱的结构仍留在统一报告中，结构最终取舍应依据候选专属PPO微调后的独立任务表现，而不是直接用此蒸馏差值淘汰。

这组默认数值是可调整的工程预算，不能保证找出所有epoch中的全局最佳策略。需要更充分检查时，设置 `--candidate-every-epochs 1`，并增大 `--promotion-count`，可让所有epoch进入扩大验证。正式2500结构、每批10结构、20epoch、BC加3轮DAgger的默认配置，选模共213个worker调用（含教师），最终全库paired nominal/robust测试为3000个worker调用；实际数量及环境步数写入 `manifest.json.selection_budget`。这些不是耗时承诺，不能直接按调用数换算训练时间。

最终对选定学生与三个教师分别执行全共同结构库的 `nominal` 和 `robust` 测试。该范围是计划中三个教师共同覆盖的结构集合，不保证等同任一单任务的全部训练结构，更不能据此证明库外结构泛化。最终测试不再用于挑选另一轮学生。

速度误差采用机身前向速度与当步命令的RMSE，只统计初始回合并排除自动重置步。当前`continuous_locomotion_evaluation_v3`仅评价持续运动，nominal和robust都要求存活完整20秒（容许0.1秒时间差）、未触发非超时失败终止、有完整有效跟踪记录（最多缺终止重置一步）。运动RMSE不得超过 **0.25 × 指令速度RMS**，没有0.10 m/s的绝对误差下限；例如指令恒为0.2 m/s，容差是0.05 m/s。沿命令方向积分的速度仍须达到命令距离的至少50%。

站立前向速度RMS的0.10 m/s门槛及站立验收项已删除，`--standing-speed-tolerance`显式报停用错误。当前三任务前向命令下限均高于0.05 m/s；采集/回放发现零速、近零速或非前进命令会报协议不符，评估报告若含站立命令段也拒绝计分，不会静默删掉这些时间或把它们算成通过。原始跟踪器保留零指令暴露统计，仅用于识别不兼容数据，不构成站立能力评价。运动指令下机器人自身停住仍会因跟踪误差或进度不足而失败；关闭的是停步指令，不是忽略运动失败。当前结果不证明停止响应、位置保持或站立抗扰能力。

新指标名为 `command_tracking_success_rate`，**不等于完成整段楼梯、能耗达标或实机验收**。旧的固定前进/楼梯净上升规则以 `legacy_basic_gait_success_rate` 保留，仅供对照，不参与选择。最终名义和随机化测试各用一个独立于选模的指定种子，当前最终测试不提供多种子置信区间。

统一入口会传递上述默认设置。底层可通过 `--samples-per-design-per-epoch`、`--validation-rows-per-design-shard`、`--replay-cache-shards` 调整拟合预算，通过 `--candidate-every-epochs`、`--screen-designs`、`--promotion-count`、`--selection-designs`、`--selection-seeds` 调整选模预算。旧 `--max-rows-per-design-shard` 已停用并明确报错。协议和选模身份发生变化，旧运行应保留原目录，新实验使用新输出目录，不能混合新旧结果续训。

### 5.1 如何验证这两项改动是否有效

先在Isaac Lab小环境确认三个任务都能初始化、执行、计分和完成一次候选晋级，再启动正式训练。对照实验分开改变数据回放和选模：基线、仅改全量可访问回放、仅改多候选闭环选择、两者都改；教师、结构、采集范围、优化步数和最终测试保持一致，新增选模计算单独报告。重点比较三任务成功率、摔倒/存活、命令跟踪，以及记录到的受扰恢复片段覆盖和恢复表现。新的选模可能增加耗时；新的回放可能需要更多优化步才有足够覆盖，不能仅凭CPU测试或机制变化声称恢复能力已经提高。

### 5.2 文献依据与运行成本

方法依据和本项目的预算设置需要分开：

- Ross、Gordon、Bagnell，AISTATS 2011，[A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning](https://proceedings.mlr.press/v15/ross11a.html)，第3节及Algorithm 3.1：在当前策略访问的状态上查询专家，聚合历轮数据后训练。它支持保留历史数据、改善学生访问状态覆盖的动机；不证明本实现的分层权重、固定梯度预算、mmap或多任务神经网络满足原文全部理论条件。
- Mandlekar等，CoRL 2021（PMLR论文集2022），[What Matters in Learning from Offline Human Demonstrations for Robot Manipulation](https://proceedings.mlr.press/v164/mandlekar22a.html)，第2节C4及策略选择实验：训练代理损失与任务成功率不同，作者在仿真中运行策略检查点评估性能。它为闭环比较候选提供直接的机器人模仿学习证据；研究任务为操作，不是本项目的腿式机器人，效果仍须本项目实验确认。
- Agarwal等，CoRL 2022（PMLR论文集2023），[Legged Locomotion in Challenging Terrains using Egocentric Vision](https://proceedings.mlr.press/v205/agarwal23a.html)，第4节、Table 1和Figure 4：报告摔倒前持续时间、行进距离及地形任务成功率，并区分爬上部分台阶和完成整段楼梯。它支持使用闭环生存与任务完成指标，不支持直接套用本项目的速度阈值或将本项目结果视为已验证。

每5epoch选候选、6结构初筛、前2名晋级、12结构×3种子、验证128行及误差门槛均为本项目工程配置，不是上述论文规定或证明最优的数值。全量可访问和重新采样能避免一次固定截断，但不能保证罕见恢复动作一定被抽到或学会。按任务/工况均衡采样也改变了样本权重，并非对全部原始行等概率训练。

当前评价规则的具体来源还需区分：20秒来自本项目原生episode配置；19.9秒下限来自允许0.1秒偏差的工程容差，与速度样本最多缺终止一步是两个不同检查。运动25%相对RMSE、50%运动进度门槛和逐结构计算损失后优先比较最差任务平均损失的排序，都是当前自定义规则，没有上述论文直接支持其数值或证明其最优。原先的运动绝对误差下限和站立验收项均已移除，具体见上一节。教师作为同工况下的连续参照，不再划分好/坏结构，也不要求每个学生必须在全部任务上严格不低于教师，才允许报告有用的蒸馏结果。

`completed.json`已取消教师和学生全部环境均无失败的联合通过门禁，也不再给出共享策略“学会/没学会”的总判断。结果标记为 `DISTILLATION_EVALUATED_REQUIRES_CANDIDATE_FINETUNING`，并保存 `requires_candidate_finetuning=true`；每个协议分别记录师生绝对表现和逐结构差值。论文应报告成功率、连续误差及失败分布，并提前明确任务完成条件；用独立验证分析阈值敏感性，避免根据最终测试结果调门槛。运动容差通过 `--tracking-rel-tolerance` 配置；旧 `--tracking-abs-tolerance` 和 `--standing-speed-tolerance` 均停用。采集协议升级为`shared_randomization_v2`，评估升级为`continuous_locomotion_evaluation_v3`；包含站立的旧数据、缓存和完成报告不能改标签当作新协议结果，旧运行保留原目录，新实验使用新输出目录。教师与学生必须一起按新协议重评，不能拿旧教师指标与新学生指标比较。

以下对比代码`380f4ee`与`89fec11`，条件为3000共同结构、每批10结构、20epoch、BC＋3轮DAgger、默认采集/选模/最终测试协议：

| 项目 | 修改前 | 修改后 | 含义 |
|---|---:|---:|---|
| 四轮合计优化更新 | 150,000 | 150,000 | 每批仍384条，训练前向/反向次数不增加 |
| 动作误差验证的样本前向数 | 57,600,000 | 230,400,000 | 每结构/来源32行变128行，验证工作量4倍 |
| 采集仿真worker调用 | 3,600 | 3,600 | 采集量未增加 |
| 教师预检与选模worker调用 | 15 | 213 | 本阶段启动次数14.2倍，环境步数28.4倍 |
| 最终全库测试worker调用 | 3,600 | 3,600 | 最终测试范围未增加 |
| 保存的epoch检查点 | 4～80 | 80 | 旧实现每次MSE创新低就另存，新实现全部保存 |

仿真采集和评估合计7215→7413次worker调用，环境步624,360,000→634,224,000。**这些数量比例不是实际总耗时涨幅**，也不能据此声称只慢2%～3%。拟合、验证、读盘及Isaac启动成本不相等。

当前mmap实现尤其存在吞吐风险：默认只缓存2个archive，而每优化批抽取24个结构/来源项。最终轮每任务约1200份分片，随机访问时缓存命中率很低，会频繁重新加载archive元数据并读取页面。mmap解决的是全量观测的常驻内存压力，不保证读取比旧内存子集更快；机械盘、共享磁盘及网络存储可能更慢。验证前向增加、实际不同样本覆盖更广、检查点保存增多，均可能增加运行时间。原始采集文件早已完整保留，因此此次回放改动本身不会按可访问行数同比扩大原始数据文件。

同样优化步数下，每条样本的重复训练减少，MSE曲线可能下降更慢；这不自动等于控制更差，也不能预先断言一定更好。正式2500结构运行前，应分别测量拟合读盘/组批、优化、验证和闭环选模时间。后续若降低开销，应优先处理缓存/预取与验证频率，再调整候选验证预算，同时保留全量可访问和闭环选模原则。当前尚无Isaac Lab或目标服务器耗时实测。

### 5.3 代表结构预算与选模耗时

默认6/12是低成本筛选预算，不是已证明充分的结构样本量。当前2500网格包含10档大腿、10档小腿和25种膝踝组合。筛选样本用于排序，最终验收仍覆盖完整共同结构库。

默认初筛每候选运行3任务×6结构×8副本=144回合；扩大验证每晋级候选运行3任务×12结构×3种子×8副本=864回合。扩大验证中每个结构、每个任务有24回合，但多种子/副本不能替代不同结构覆盖。

| 初筛/扩大结构数 | 每轮学生选模worker调用 | 全四轮含教师worker调用 | 选模总环境步数 |
|---|---:|---:|---:|
| 6/12（当前默认） | 48 | 213 | 10,224,000 |
| 12/30（可选折中） | 78 | 345 | 24,336,000 |
| 20/60（可选扩大） | 132 | 588 | 47,040,000 |

上表固定每批10结构、每轮4候选、晋级2个、扩大3种子、BC＋3轮DAgger，最终全库测试不包含在其中。每个worker都要启动进程、加载资产、建场景、执行1000控制步并退出；20秒是模拟时域，不是实际耗时。当前没有可比的三任务robust评估实测，历史USD转换或18环境初始化耗时不可套用。

条件估算仅用于预算：若服务器实测平均每worker为1分钟，213/345/588次分别约3.55/5.75/9.8小时；若为3分钟，则约10.65/17.25/29.4小时。它们不是对当前服务器的预测，亦不含采集、拟合和最终全库测试；冷启动与首次资产准备可能增加耗时。现场应从 `processes/.../exit.json.seconds` 分别获取楼梯/负重/跑步以及教师/学生作业耗时，再按各类作业数求和。默认预算本次保持6/12，扩大结构数应结合实测成本和候选排名稳定性决定。

## 7. 暂停恢复与记录兼容

统一入口会定位原目录并传递普通 `--resume`。人工 Ctrl+C 暂停后需要显式恢复：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 蒸馏 --gpu 0 --resume-paused
```

底层 `distill.py` 同样支持 `--resume-paused`，该选项包含 `--resume` 的含义。恢复时必须使用原计划、原预算和原协议；先校验身份，再把暂停标记归档到 `pause_history/`。改变参数或源码会拒绝恢复，并保留暂停标记。需要改变实验定义时新建输出目录，不通过删除身份记录强行续写。

| 中断位置 | 实际恢复行为 |
|---|---|
| 采集期间 | 复用已有 `data_commits/`；未提交作业换新attempt重新采集 |
| BC/DAgger拟合期间 | 未完成本轮拟合会从本轮起点重做；没有恢复该次拟合的minibatch/Adam进度 |
| 已完成拟合、选模期间 | 校验 `fit_round_*.json` 中的模型身份，复用已提交评估；补齐剩余候选 |
| 最终测试期间 | 保留选定模型与已提交测试，补齐剩余任务/结构/协议 |
| 已完成 | 校验最终actor身份后返回已有结果，不重复启动训练 |

各轮拟合原本就从上一轮闭环赢家初始化新的Adam；这与候选PPO的完整学习状态续训不同。单独存在一个epoch模型，并不等于整个拟合作业已提交。进程锁防止两个协调器同时写同一输出目录；JSON和共享actor在完整写入、关闭后原子发布，不覆盖已有结果。

`summary.json` 和 `data.pt` 的记录分为：

- `requested_configuration`：入口请求值，例如偏航默认0.05、AMP固定速度参数2。
- `applied_configuration`：配置后实际生效的命令、初态、学生噪声、延迟、随机化事件范围。它是范围定义，不是每一步已实现的状态轨迹。
- `collection_protocol`：启动时冻结的版本、强度、源码哈希；若执行中源码发生变化，拒绝写出冒用该身份的结果。
- `scenarios.json`、`payload_audit.json` 与逐回合记录：分别追踪实际地形/载荷分配及运动测量。

例如 `robust` AMP实际命令范围1.5–2.5 m/s，应读取 `applied_configuration.commands`，不能把请求参数2误当作全程固定速度。`ppo_updates`为唯一更新计数；蒸馏actor为0。旧文件只有大写计数时可无歧义读取并规范化，同时含互相矛盾大小写计数则报错。
