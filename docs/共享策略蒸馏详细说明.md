# 三个跨形态专家蒸馏成一个共享策略

共享学生作为后续硬件选型的统一控制器起点。三个专家各自提供动作标签，学生学习根据任务和物理参数给出动作。每个 BO 候选随后从同一份学生权重独立微调。硬件的排序依据是微调后的固定工况实测代价。[研究备忘录](跨形态多任务共享策略蒸馏与硬件选型研究备忘录.docx)

## 启动

在仓库根目录运行。已完成三个专家训练且使用一次性迁移库时，命令如下。新生成的结构库省去 `--migrated`。人工暂停后在同一命令末尾加 `--resume-paused`。

```bash
conda run --no-capture-output -n robo_cjl python start.py 蒸馏 --migrated --gpu 0
```

入口绑定三个已完成专家的检查点、相同物理结构和 AMP 原生参考。AMP 教师使用训练时的观测排列与归一化；共享学生使用十帧历史。库中已有的参考按运动学匹配。将来添加实际运动学不同的结构时，应先生成并验证它自己的参考动作。

## 一个学生怎样训练

| 阶段 | 在仿真里执行动作的策略 | 用于训练的标签 | 本轮产物 |
|---|---|---|---|
| 初始行为克隆 | 冻结教师 | 教师在自身访问状态上的动作 | 初始学生 |
| DAgger 第 1 轮 | 初始学生 | 教师在学生实际访问状态上的动作 | A |
| DAgger 第 2 轮 | A | 同上 | B |
| DAgger 第 3 轮 | B | 同上 | C |

每轮在三个任务上依次采样。每个任务一次装入全部 **400 个结构、4096 个环境**。采样网格从已有长度中取接近等间距的 4 档大腿、4 档小腿，组合全部 5 款膝电机与 5 款踝电机。每结构有 10 或 11 个环境，控制频率为 50 Hz，每轮每环境采 5 秒，每 5 个控制步保存一次标签。一次正常完整采集对应每任务 204,800 条记录。负重按任务分布采集，10 kg 是后续 BO 固定工况。每个结构的楼梯训练使用六种地形，额外 4 或 5 个环境承担独立动作验证。单结构的离线验证只覆盖其中 4 或 5 种地形；三任务均按物理环境划分训练与验证。

拟合使用累计采集数据，每轮 **10 个 epoch**，按任务、结构和采样来源平衡抽样。epoch 表示一次按既定样本预算进行的训练，包含多次梯度更新。默认四轮随机化强度依次为 0.25、0.50、0.75、1.00。每轮传递最后一个 epoch 的模型，程序存储的 epoch 从 0 编号，第 10 个对应索引 9。每任务每轮写一份回放，共 12 份。默认保留最多 12 个只读内存映射，训练按需读取小批量，减少跨轮采样时反复打开大文件。离线动作误差用于诊断。共享 critic 在之后的候选 PPO 微调阶段训练。

## 如何从 A、B、C 中选一个

正式结构库有 2500 种形态。选模只用固定的 50 个，每种膝踝电机配对各两个：一个来自 400 个蒸馏结构，另一个来自剩余结构。先排除第 21 组用于 BO 定标的全部物理结构。算法优先补足出现次数少的腿长档位，同一电机配对尽量拉开腿长。选样依赖物理参数键，可跨三个任务的不同 ID 对齐。

三个模型独立控制机器人，各跑上楼、负重、跑步，在相同随机化条件下使用三个共同种子（20261117、20261119、20261120）。教师在相同结构和种子上提供一次可复用的基线。每个试次取 20 秒，当前判定要求存活至少 19.9 秒、运动方向进度达到命令行程的 50%、运动阶段前进速度 RMSE 不高于指令 RMS 的 25%，且跟踪测量完整。此处考察持续步态。BO 的楼梯登顶判据另见评分说明。

每个结构按 `max(教师通过率 − 学生通过率, 0)` 计算落后幅度。各结构在任务内等权，首先比较三个任务中最大的平均落后幅度，较小者优先。依次比较三任务平均落后幅度、学生通过率、存活比例、跟踪测量覆盖和速度误差，完全持平时取较早轮次。程序冻结胜出的模型，蒸馏到此完成。报告能支持对这 50 个结构的判断，全库通过率没有测量。

## 查看产物和下一步

| 实验根目录下的文件 | 用途 |
|---|---|
| `shared_plan/plan.json` | 冻结的教师、结构库及身份 |
| `shared_policy/manifest.json` | 400 个采集结构、两批 50 的结构键、种子和预算 |
