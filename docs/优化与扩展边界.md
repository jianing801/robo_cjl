# BO、新结构与共享PPO的边界

## 已有主线

当前正式主线是三任务匹配的完整结构库 → 三个跨形态专家 → 冻结教师 BC/DAgger → 共享 Actor → 候选联合微调 → 固定工况评价和约束 BO。[操作流程](跨形态多任务共享策略训练流程.md#完整流程) · [三任务 BO](三任务BO评估与结构搜索.md)

## Rough BO是另一套已定义协议

`rough_bo`使用历史 Rough 教师作为候选微调起点，包含独立 OCD 初始点、性能 GP、可行性分类及评分规范。三任务入口复用 GP 实现，采用新版 2500 结构共同库、共享 Actor 和独立的三任务评分。

历史源码已归档，`rough_bo/start.py`可按检查点SHA恢复独立审计树；已有合法冻结树继续使用。配置输入和完整步骤见 [Rough BO说明](../rough_bo/粗糙地形优化说明.md)、[约束BO协议](../rough_bo/约束贝叶斯优化方法.md)。原生源码、教师模型和实际bank是必需输入，模型不在Git里。

启动器支持`--check-only`，仍会检查模型/源码并选择GPU，不等于纯CPU检查；不要在没有相应教师文件时直接照抄默认路径。底层控制器的旧Windows默认路径不是服务器部署配置，应显式传参或使用启动器。

## 固定结构共享PPO实验

`multitask_morphology/shared_policy/joint_finetune.py`当前明确寻找大腿0.25m、小腿0.30m、膝10010L、踝RS06这一种结构，再联合三任务采样更新共享Actor和新Critic。它不是全库跨形态PPO接口。

当前10档网格并不精确包含0.25/0.30这组腿长，因此不能把该脚本直接列为本次训练结束后的正式命令。要扩展为全库共享PPO，需要明确结构选择、各任务采样和奖励尺度、身份、恢复策略及原生短测；这不属于仅补文档就已经完成的能力。

## 新结构与新参考

共享计划限定教师共同结构库中的ID。新腿长、不同电机、离网格结构或新的GP/曲线版本，需要实际生成URDF、审计参数和动作顺序，并重新建立合法身份。新运动学必须生成对应AMP参考动作；不能按近似腿长借用，也不能直接修改共享计划的ID列表绕过检查。

相同运动学只换执行器时，参考求解可按已验证运动学标识复用，但库仍要正确绑定实际bank和URDF身份。是否具备行走能力必须通过教师/学生实际闭环评估，不能从运动学参考存在推断。

## 遗忘评估

原理上可利用各阶段完整检查点评估同一批结构，得到学习/遗忘轨迹。但当前共享流水线没有自动遗忘矩阵功能；评估协议必须固定任务、命令、负载、地形、初始分布和门槛。训练Mean reward锯齿不能直接当作遗忘量。
