# AMP 专家训练版本与启动

现有四个入口。前三个使用**时空轮换**，每组在 4096 个环境中布置 50 种结构，每 50 次 PPO 更新重建场景换组。按正式分组表遍历 2500 种结构一轮需要 50 组，5000 次更新共跑两轮。第四个是独立的**空间域随机化**对照，2500 种结构同时进入 4096 个环境，5000 次更新期间固定各环境的结构。

## 四个版本有什么区别

| 版本 | 场景里的结构 | 首回合起始计数 | 每组额外仿真步 | 默认输出目录（相对实验根） |
| --- | --- | --- | ---: | --- |
| 时空轮换 · 原版 | 50 种，每 50 次更新换组 | 首组及每次换组从 0 开始 | 0 | `experts/amp/`，已有实验按启动记录选择 |
| 时空轮换 · 错开回合与预热版 | 50 种，每 50 次更新换组 | 首组及每次换组按结构错开计时 | 1096 | `experts_staggered/amp/` |
| 时空轮换 · 首回合计时器随机版 | 50 种，每 50 次更新换组 | 首组及每次换组给每个环境独立抽取 0–999 步 | 0 | `experts_random_episode/amp/` |
| 空间域随机化 · 2500 结构 | 2500 种同时训练，全程固定 | 整场训练开头给每个环境独立抽取 0–999 步 | 0 | `experts/spatial_amp_all2500_时间戳/` |

此前称作“回合延长版”的是表里的**错开回合与预热版**。这版每组先按结构错开回合计时，再用当前策略实际预热 1096 步。预热步不进 PPO，可能被截短的首回合从回报统计中排除，后续完整经历的回合用来建立 `Mean reward` 窗口。四个入口的 AMP 单回合超时上限均为 **20 秒（1000 个控制步）**。一个环境完成回合重置后，计数从 0 开始。[预热细节](错开回合专家训练说明.md)

**首回合计时器随机版**直接调用普通 AMP 的随机计时逻辑，每次换组随机一次后直接开始 PPO。即使首回合因初始计数而缩短，结束时也正常进入 `Mean reward` 统计。三种轮换版均沿用同一分组表、结构库和正式 PPO 更新预算。[随机计时版续训说明](AMP换组随机回合对照实验.md)

**空间域版**中，1596 种结构各占两个环境，其余 904 种各占一个环境。它保留全局 `Mean reward`，关闭逐结构日志，并用向量化实现分结构批次采样。它没有换组引起的场景重建与回报窗口重置。[空间域实验细节](AMP空间域随机化对照实验.md)

## 在服务器 tmux 中启动

以下命令使用已经准备好的迁移库，示例使用 3 号卡。先在服务器终端打开 tmux：

```bash
tmux new -s amp-expert -c /data/chenjiale/robo_cjl
```

进入会话后，从下面四条中**只选一条**。替换最后一位 GPU 编号即可换卡。

**时空轮换 · 原版**

```bash
conda run --no-capture-output -n robo_cjl python start.py amp --migrated --gpu 3
```

**时空轮换 · 错开回合与预热版**

```bash
conda run --no-capture-output -n robo_cjl python start_staggered.py amp --migrated --gpu 3
```

**时空轮换 · 首回合计时器随机版**

```bash
conda run --no-capture-output -n robo_cjl python start_amp_random_episode.py --migrated --gpu 3
```

**空间域随机化 · 2500 结构**

```bash
conda run --no-capture-output -n robo_cjl python start.py amp-spatial --migrated --gpu 3
```

四条命令都使用 `robolab/logs/multitask_full2500_physical_migrated/` 下的实验资源。已经准备好 AMP 库、USD 和参考动作时可以直接复用。[迁移和资产准备](USD资产准备启动说明.md)

按 `Ctrl+B`，松手后按 `D`，训练留在 tmux。用 `tmux attach -t amp-expert` 回去查看。会话名已存在时可以直接连接已有会话。启动后看终端打印的运行目录，同目录的 `plan.json` 记录训练配置。每个轮换版本从自己的已提交组断点续训。空间域入口每次启动会创建一个新时间戳目录。

## 怎么做对照

- 要单独看随机计时对锯齿的影响，比较两种轮换版，即原版和首回合计时器随机版。看 `Train/mean_reward` 和 `Train/mean_episode_length` 在同一组内前后的变化。新版每组仍按已结束回合计算原指标。
- 比较预热版时，记下每组额外的 1096 个仿真控制步。除了 PPO 更新数，还可以按总仿真步数和训练时长报告结果。
- 比较空间域和时空轮换时，以同样使用普通 AMP 随机首回合计时逻辑的轮换随机版作参照。报告从启动到结束的时长与正式 PPO 更新速度，并注明场景覆盖、逐结构日志和批次实现的差别。
