# 结构分组轮换训练方法

## 1. 先区分结构、环境和更新

**一种结构＝一组大腿/小腿长度＋一组膝/踝电机搭配；一个环境＝这台机器人的一个仿真副本。** PPO的一次更新是采样后的一轮策略优化，不等于一个完整回合，也不等于换一次结构。

本方法在单个专家任务内把多结构空间并行和结构组时间轮换结合起来。三个任务先各训自己的专家，之后才蒸馏成共享策略。

## 2. 全库怎么组成

| 变量 | 取值 |
|---|---|
| 大腿长 | 0.20–0.40m，10档，含两端 |
| 小腿长 | 0.25–0.45m，10档，含两端 |
| 膝电机 | 5款 |
| 踝电机 | 5款 |
| 腿长搭配 | 10×10＝100种 |
| 电机搭配 | 5×5＝25种 |
| 完整结构 | 100×25＝2500种 |

腿长按各自范围等间距取样；实际URDF、质心、惯量、执行器曲线及形态条件按每种结构生成。负重另有附件，AMP使用与真实运动学匹配的参考动作。三个任务的基础设计变量一一对应。

## 3. 怎么分成50组

每组50种，整轮50组。不是分别随便抽腿长和电机，而是**联合构造完整的四元组**，再检查以下硬条件：

| 每一组都满足 | 数量 |
|---|---:|
| 每一种膝—踝电机组合 | 恰好2种结构 |
| 每一档大腿长度 | 恰好5种结构 |
| 每一档小腿长度 | 恰好5种结构 |
| 每一款膝电机 | 恰好10种结构 |
| 每一款踝电机 | 恰好10种结构 |
| 全组 | 50种完整结构 |

一整轮50组正好覆盖2500种结构，不重复、不遗漏。因此，同一电机组合会在整轮遇到全部100种腿长搭配；不要求在一个组里见全所有腿长。

边际计数相等还不够：某款电机仍可能在短时间内偏向某个腿长区域。因此还对**每款电机对应的二维腿长分布**检查连续1、5、10组窗口，兼顾短、中、长大腿和小腿组合，而不是仅看电机出现次数。

## 4. 用的具体算法

这是自定义的“**精确循环构造＋候选筛选＋模拟退火排列组顺序**”，不是在线根据奖励临时抽组，也不是直接照搬某篇论文的算法。

### 先构造满足硬条件的组

将25种电机组合分成5块，每块5种。每块各分配两组0到4的排列参数 `a` 和 `z`。对于组索引 `(r,d)`，`r=0…4`、`d=0…9`，每个电机组合选择两个腿长索引：

```text
# t 是大腿档位索引，c 是小腿档位索引，从0开始。
t = (r + a) mod 5
c = (t + d + z - a) mod 10

# 同一电机组合在这一组里对应两种不同腿长搭配。
第一个点：(t, c)
第二个点：(t+5, (c+5) mod 10)
```

两点跨越大腿的短、长两半，小腿索引也相隔5档。5种组合组成一块，每块覆盖10档大腿和10档小腿各一次；5块合起来每个腿长档位各5次。遍历50组后，每种电机组合覆盖全部100个腿长格子。

### 再筛选和优化顺序

每个随机种子生成64张满足硬条件的候选表，选择覆盖较好的一张；随后做12000步模拟退火，只交换两个完整组的顺序，**不改变每组50种结构的组成和硬配额**。

优化指标是每款电机在3×3二维腿长区域上的分布与该电机全库分布的差异。用总变差距离TV衡量，兼顾连续1、5、10组的平均和最坏情况。接受少量暂时变差的交换帮助跳出局部最优，最终保留搜索中最好的排表。

试验比较了种子42、43、44；按事先设定的目标选择种子43并冻结。训练过程中读取冻结表，不重新搜索，不根据奖励挑组。它是工程可行构造，没有全局最优证明。

## 6. 每组怎么放进4096个环境

```text
50种结构 × 每种81个副本 = 4050个环境
剩余46个环境分别再分给46种结构
合计4096个环境
```

所以每种结构有81或82个副本，共同采样并更新本任务的同一个形态条件策略。每个任务在每组中仍更新一套策略。

跨轮时，组内顺序按 `cycle×46 mod50` 旋转，轮换额外46份副本的归属；组成员和组的训练顺序保持冻结。不声称有限预算内每个结构获得的总副本步数完全相等。

## 7. 实际训练的时间顺序

```mermaid
flowchart LR
    A[第1组50种 更新0至49] --> B[第2组50种 更新50至99]
    B --> C[依次到第50组 更新2450至2499]
    C --> D[下一轮从第1组继续 更新2500起]
    D --> E[达到任务绝对预算后结束]
```

每组完成50次PPO更新后保存提交记录和检查点，再重建下一组的环境。策略、critic、Adam优化器、归一化状态及绝对迭代数按原协议恢复；环境状态重新初始化，不声称物理轨迹逐位连续。

| 任务 | 总更新 | 换组阶段数 | 覆盖轮次 |
|---|---:|---:|---|
| Rough | 12000 | 240 | 完整4轮，再训练第5轮前40组 |
| 负重 | 12000 | 240 | 完整4轮，再训练第5轮前40组 |
| AMP | 5000 | 100 | 完整2轮 |

因此Rough/负重最后一轮只有40组，一部分结构比另一些多训练50次更新；这来自固定12000预算，不把最后部分轮次说成完整均匀覆盖。负重载荷阶段按全局更新编号变化，不因换组重置到最初阶段。

## 8. 怎么判断分组与训练是否正确

程序检查完整ID覆盖、电机组合配额、两个腿长轴配额及冻结表哈希。组号、全局更新范围和design_ids写入每组记录，原始证据用于确认实际轮换，不只看屏幕奖励。

换组后的Mean reward可能回退：机器人与环境更换、回合重新开始，以及“最近完成回合”的统计窗口都会影响曲线。因此还需按任务和结构看完整回合、是否摔倒、是否向前移动，以及统一配对评估。不能仅用锯齿曲线证明遗忘或训练失败。

目前离线结果显示：连续5组、10组窗口的平均二维TV较旧分层轮转基线分别降低约44.5%、47.0%。这些是覆盖指标，不代表已证明减少遗忘或改善PPO步态。原始算法、单组局限及独立审计见[分组算法与验证](../robolab/experiments/multitask_morphology/scheduling/分组算法与验证.md)。

## 10. 单遍逐形态对照怎么启动

三个任务沿用同一张冻结表的结构顺序，每次让 4096 个环境训练同一种结构。2500 种结构各进场一次。切换时沿用同一个策略及其优化器，AMP 还保留判别器和归一化状态。

| 任务 | 总更新次数 | 每种结构的更新次数 |
|---|---:|---|
| Rough | 12000 | 前 2000 种各 5 次，后 500 种各 4 次 |
| 负重 | 12000 | 前 2000 种各 5 次，后 500 种各 4 次 |
| AMP | 5000 | 每种 2 次 |

在仓库根目录执行对应任务的命令，按实际空闲显卡改卡号。

```bash
conda run --no-capture-output -n robo_cjl python start.py rough-serial --gpu 0
conda run --no-capture-output -n robo_cjl python start.py backpack-serial --gpu 0
conda run --no-capture-output -n robo_cjl python start.py amp-serial --gpu 0
```

入口复用已登记的任务 USD 缓存。AMP 另外读取结构库对应的 `references/library.json`。默认使用迁移后的结构库，已有资产放在其他目录时加 `--root` 指定。末尾加 `--dry-run` 可以预览。

训练输出分别写到实验根目录下的 `experts/serial_rough`、`experts/serial_backpack` 和 `experts/serial_amp`。每完成一种结构保存一个阶段断点。再次执行同一条命令会使用已有计划续训。有暂停标记时加 `--resume-paused`。首组中断且尚无阶段断点时，加 `--restart-initial` 从独立目录启动首组。
