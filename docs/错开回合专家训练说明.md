# 错开回合专家训练说明

## 为什么原曲线会出现锯齿

Rough、负重和 AMP 的 TensorBoard 指标 `Train/mean_reward` 取最近 100 个**已结束回合的累计回报**的平均值。换结构组时会创建新的仿真场景，原组的回合统计窗口随之清空。新场景里的环境几乎同时开始回合，先进入窗口的往往是提前摔倒或终止的短回合。能够继续运行较久的回合随后才结束并进入窗口，曲线就容易在组初偏低、组末回升。这种波动和结构难度、策略实际表现的变化可能同时存在。

这条曲线用于观察训练过程。判断旧专家是否适合蒸馏，要在对应任务的共同结构上评估步态、提前终止和前向进展。记录窗口的变化不会直接参与 PPO 更新。

## 为什么加入错开回合预热

新版在每次换组完成场景初始化后，先按结构给并行环境分配分散的初始回合计数，再用当前策略实际推进仿真。每个环境在预热中首次结束的回合可能被初始计数缩短，因此从回报统计中丢弃。从真实重置开始并结束的后续回合进入同一个 100 回合窗口，其中也包含真实的提前终止。这样进入第一代 PPO 前，日志已经有完整回合可统计，各环境的回合结束时间也更分散。

预热不做 PPO 更新，预热步不进入 PPO rollout。奖励公式、策略配置、正式采样步数和更新预算沿用各任务原设置。预热会改变正式采样开始时的场景状态，还会增加实际仿真交互，因此新版是一轮独立训练。AMP 的预热长度为最大回合 1,000 步加上 4 次 24 步采样，共 **1,096 个控制步**。Rough 和负重按各自最大回合步数和每环境采样步数计算。论文若以仿真交互量为横轴，需把预热步也计入。

一次 AMP 实测中，第 551–600 代的组初和组末各 10 代平均值，旧版为 **−0.22 和 11.81**，错开回合版本为 **10.57 和 10.67**。这是这两次 AMP 运行的观测，对 Rough、负重和最终策略表现仍需分别验证。用新版曲线展示预热实验时，在图注注明训练版本。蒸馏和 BO 的结果注明实际使用的教师检查点。

## 启动哪一套

在仓库根目录运行 `conda activate robo_cjl`，然后按任务选用下面的命令。以下命令用 GPU 0，换卡时修改最后的卡号。原卡上还在训练时，使用有足够空闲显存的卡，或等待原任务结束。新版沿用原生 GPU 租约和同结构库进程检查，检测到冲突时会停止新启动。

| 任务 | 原入口 | 错开回合入口 | 正式 PPO 更新预算 |
| --- | --- | --- | --- |
| Rough | `python start.py rough --gpu 0` | `python start_staggered.py rough --gpu 0` | 12,000 |
| 负重 | `python start.py 负重 --gpu 0` | `python start_staggered.py 负重 --gpu 0` | 12,000 |
| AMP | `python start.py amp --gpu 0` | `python start_staggered.py amp --gpu 0` | 5,000 |

两套入口默认使用 `robolab/logs/multitask_full2500_physical` 下的已有资源。使用此前迁移好的结构库时，在命令末尾加 `--migrated`。使用自定义实验根时，加 `--root /你的/实验根`，和 `--migrated` 二选一。新入口可加 `--dry-run` 查看将使用的目录和启动参数。

原版读取和写入 `<实验根>/experts/` 下自己的训练记录。新版使用 `<实验根>/experts_staggered/{rough,backpack,amp}/` 下各自的训练记录。新版从头建立自己的检查点链，新版续训只接自己的已提交组。有已提交组断点时，确认恢复可在启动命令末尾加 `--resume-paused`。首组中断且没有已提交断点时，入口会保留现场。旧入口、旧训练目录和旧蒸馏选取规则保持原样。

### 共用已经准备好的资源

两套入口共用同一实验根下对应任务的 `banks/<任务>/bank.json`、URDF 和已完成的 USD。新版优先使用 `启动记录/<任务>_asset_cache.json` 指向的缓存。如果以前没有登记索引，新版会检查对应的资产准备目录和旧专家目录，选择带同一结构库完成证明的缓存。AMP 也会复用 `references/library.json` 和对应参考动作。训练仍按原生流程校验资产，可能记录缓存快检凭据，结构库、USD 和参考动作内容保持原样。

已有结构库、有效的 USD 缓存和 AMP 参考动作时，直接启动新版训练。资源缺失或校验失败会在启动阶段报错。按原流程补齐缺项后重试，资产和参考动作准备不启动专家训练。例如缺少负重 USD 或 AMP 参考动作时，可以分别运行以下命令。

```bash
python start.py 资产 --任务 负重 --gpu 0
python start.py 参考动作 --gpu 0
```

如果训练使用 `--migrated` 或自定义 `--root`，准备资源时也使用同样的实验根。没有结构库时，先按[原专家训练流程](专家训练与运行操作.md#结构库与参考动作准备)准备对应结构，再按 [USD 资产准备说明](USD资产准备启动说明.md)完成缓存。

## 查看进度和确认训练来源

- 训练进度和原始 `Mean reward` 见运行目录中的 `attempts/session_*/train/stdout.log`。TensorBoard 使用 `Train/mean_reward`，横轴为更新索引。按已完成更新次数绘图时，使用索引加 1。AMP 的任务回报记录在这个字段，风格回报和混合回报分别记录在 `AMP/mean_style_reward` 和 `AMP/mean_total_reward`。
- 新版运行目录的 `plan.json` 记录冻结的错开回合方案，`commits/` 保存每组已提交断点，`completed.json` 记录完成的更新预算与最终检查点。每次预热的步数、排除的首回合以及完整回合数量，见 `EPISODE_PHASE_WARMUP_COMPLETE` 日志。
