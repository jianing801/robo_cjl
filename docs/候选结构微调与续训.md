## 候选选择和启动

默认实验根目录是 `robolab/logs/multitask_full2500_physical/`。以下命令显示共同结构表的前十个结构及三个任务各自的 ID。

```bash
cd /data/chenjiale/robo_cjl
conda run -n robo_cjl python -c 'import json; from pathlib import Path; p=json.loads(Path("robolab/logs/multitask_full2500_physical/shared_plan/plan.json").read_text()); b=json.loads(Path(p["shared_bank"]).read_text()); [print(r["key"], r["design_ids"]) for r in b["structures"][:10]]'
```

`key`依次为大腿长度、小腿长度、膝电机完整型号、踝电机完整型号。`design_ids`分别对应`stairs`、`backpack`、`run`；三者ID不同也可对应同一结构。用其中一个ID即可，程序将完整参数键映射回三个原生库，并检查各任务唯一匹配。

以下`真实结构ID`是占位值，替换为上面查到的stairs ID：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 微调 --gpu 0 --candidate-task stairs --candidate-design-id 真实结构ID --finetune-updates 100
```

独立入口 `start.py 微调` 和正式 BO 默认都做 100 次更新。已有同一候选的旧预算或旧优化配置结果时，用 `--finetune-output` 指定新目录。指定负重或跑步 ID 时，同时改 `--candidate-task backpack` 或 `run`。默认输出到 `candidate_finetuning/<结构键摘要>/`，每个候选隔离。默认读取 `shared_policy/completed.json` 中选出的共享 actor，并校验输入 schema 及教师与结构身份。

可选参数：

| 参数 | 用途 |
|---|---|
| `--dry-run` | 预览精确命令和输出路径，不启动训练 |
| `--finetune-output /绝对路径/新目录` | 同一候选的新预算或新协议实验另建目录 |
| `--finetune-evaluation-seeds 20261118,20261121` | 微调后独立测试种子；须与微调种子不同 |
| `--evaluation-profile nominal/robust/both` | 最终评价协议，默认both |
| `--min-command-progress-ratio` | 实际前进量须达到的指令行程比例，默认 0.5，随实验身份冻结 |
| `--resume-paused` | 明确恢复人工暂停；原预算不变 |

底层入口是`robolab/experiments/multitask_morphology/finetune.py`。除了上述ID方式，还支持`--design-key 大腿米 小腿米 膝型号 踝型号`，与`--design-id`互斥；必须精确存在于计划选定的共同结构库中。底层需同时传`--plan`、`--student`、`--output`，自定义蒸馏输出目录的actor可由此接入。

## 微调实际做什么

| 配置 | 当前实现 |
|---|---|
| actor | 从蒸馏学生初始化；同一候选的三个任务共享一个actor，通过任务条件区分 |
| critic | 新微调实验初始化一个共享MLP critic，256/128隐藏层；续训恢复原critic |
| 每任务环境数 | 8；三个采样器位于同一获准GPU，每任务独立Isaac进程 |
| 每次更新数据 | 每任务24控制步×8环境，三任务合计576条transition |
| 同步方式 | 三任务都完成当前actor的采样后，才做本次联合更新 |
| 优化 | 每次更新4个epoch、minibatch192；actor学习率3e-6，critic学习率1e-3；梯度范数上限1 |
| PPO参数 | clip 0.2，gamma 0.99，GAE lambda 0.95，固定动作标准差0.05 |
| 优势处理 | 各任务批次分别归一化优势，再合并训练；奖励采用原生任务定义 |
| 运行位置 | Isaac采样器使用选中的GPU；当前协调器actor/critic优化在CPU |
| 更新预算 | 每结构默认 100 次 PPO 更新。当前每次采 576 条控制步样本，合计 57,600 条 |
| PPO 优化 | 每批采样数据练 5 个 epoch，每个 epoch 分 4 个小批，每次 PPO 更新执行 20 次优化器更新 |

统一入口总是使用`robust`满强度1：各任务保留自己的物理随机化和扰动配置，学生使用统一观测接口及对应任务噪声。它不继承蒸馏最后一次调用的`nominal`开关，不重新从0.25开始课程。底层允许显式nominal消融，应另建实验目录。

站立命令仍关闭，楼梯保持六组离散规格。每结构8个楼梯副本在六档上的数量为[2,2,1,1,1,1]，不是六档等权。教师参数和归一化统计不更新；AMP的判别器用于原生风格奖励。此次没有修改此前暂缓的AMP终止观测处理。

候选计划只收窄三个任务的实际结构 ID。新版共享 Actor 沿用从共同结构库冻结的 28 维物理量与归一化参数。

## 暂停恢复与提交边界

普通故障后重复相同统一命令，入口自动附加`--resume`。Ctrl+C产生`USER_PAUSED`后，在原命令末尾加`--resume-paused`：

```bash
conda run --no-capture-output -n robo_cjl python /data/chenjiale/robo_cjl/start.py 微调 --gpu 0 --candidate-task stairs --candidate-design-id 真实结构ID --finetune-updates 100 --resume-paused
```

`--finetune-updates 100`表示本实验总共100次，不是在断点上再加100次。恢复会校验候选、初始actor、源码、协议、预算和评估定义；不一致则停止并保留原记录。若要扩大预算，需设计新实验，不把不同预算结果混入原链。

每次完整更新按顺序保存学习状态tensor，再发布对应JSON提交记录；恢复只承认已提交的连续序列，忽略未提交的孤立tensor。第0个提交保存初始状态。保存内容包括：

- actor全部参数及观测归一化buffer；critic参数；Adam状态和参数组学习率。
- 已完成PPO更新数；协调器的PyTorch CPU、Python、NumPy随机数状态。
- schema、网络架构、运行manifest身份与更新损失记录。

如果中断发生在更新中途，重启从最近完整提交恢复，该未提交更新重做。**不恢复PhysX场景、环境回合、GPU采样器随机数状态或半个rollout**；三个环境重新初始化，使用新attempt和记录下来的采样种子。学习状态连续不等于仿真轨迹逐步完全复现。

若训练已完成但独立评估中断，直接恢复最终学习状态并补测，不重复PPO。所有结果齐全才写`completed.json`。已完成的实验再次运行只校验结果，不重新训练。

## 通信和实验记录

`persistence.py`统一负责JSON、actor和PPO tensor的完整写入与原子发布：同目录临时文件写完、flush/fsync并关闭后，通过排他硬链接发布最终路径。读者只会看到不存在或完整文件；已有文件不会被覆盖。底层文件系统须支持硬链接（常见Linux文件系统及NTFS支持）；不支持时明确报错，不退化为存在竞态的直接写入。本机验证为Linux，Windows锁分支尚未实测。

每次启动创建独立`attempts/<会话ID>/`；请求和结果绑定会话、manifest、actor SHA256、更新编号和协议。协调器同时检查张量形状、有限值及终止掩码，不接收旧会话结果。操作系统进程锁防止两个协调器写同一实验；正常退出会关闭采样器，强杀后的残留进程仍需在实际服务器核查，不能把新会话隔离当作GPU资源已释放的证明。

每个worker保留`randomization_audit.json`、`physics_audit.json`等有效配置记录；独立评价summary区分请求值和生效范围。导出actor只有小写`ppo_updates`，不会再同时出现大写0与小写N。`critic_trained=true`只说明本次有critic学习，导出actor本身不携带critic；完整续训必须读取`checkpoints/`。

## 独立跟踪评价与固定工况 BO

通过 `start.py 微调` 单独启动候选时，微调后冻结 actor，使用独立于训练的种子，默认分别运行 nominal 和 robust。robust 评价始终满强度 1，即使底层显式使用较低训练强度或 nominal 消融，测试定义也不会随之降低。每个任务仍测 8 个环境、1000 控制步，默认种子 20261118，可显式增加种子。

常规微调报告每回合评估 20 秒，要求无失败终止、存活至少 19.9 秒、行程测量有效，且实际行程默认达到指令行程的 50%。三个任务都用水平航向速度累计实际行程，并记录该速度的回合均值。程序保存各任务的原始记录和统计。

`candidate_result.json`提供：

| 字段 | 含义 |
|---|---|
| `candidate.structure_key / design_ids` | 真正微调和评价的物理结构及任务ID映射 |
| `student_sha256 / ppo_updates / manifest_sha256` | 最终actor及实验身份、微调预算 |
| `profiles.nominal / robust` | 各任务统计和原始评估报告索引 |
| `evaluation_criteria / evaluation_seeds` | 本次评价判据与种子 |
| `requires_evaluation=false` | 本次要求的后评估已完成；不表示各任务全部成功 |
| `scalar_objective=null`、`requires_bo_objective_definition=true` | 跟踪报告本身不包含 BO 的固定工况采集和归一化分数 |

正式 BO 以 `--training-only` 调用微调程序，读取 `training_completed.json` 核验冻结 Actor，随后直接运行三个任务共三个固定工况试次，统一用种子 `20261118`。测量能耗、前向速度 RMSE、电机负荷或躯干角速度。摔倒或水平净前进距离低于指令行程的 20% 时，该正式试次记为失败，结构失去最终排名资格。可通过 `--finetuned` 复用同一候选、同一起始模型、同一预算及 PPO 优化配置下的完整微调目录。[三任务 BO 评估与结构搜索](三任务BO评估与结构搜索.md)

## 查看微调 reward

每个候选的 `training_reward.csv` 按 PPO 更新和任务各写一行。每次更新每项任务采 24 步 × 8 个环境。优先看 `mean_ppo_step_reward` 的趋势，它使用 PPO 实际接收的奖励。也保存 `mean_environment_step_reward`，AMP 中两者的差异来自冻结的风格奖励。回合累计回报只在完整结束的回合上统计，同一采样会话内跨更新累积。超时和其他提前终止的次数分别列出。没有完成回合时，回合回报栏为空。历史更新如果未记录 reward，对应值为空。

`mean_reward.csv` 每次 PPO 更新写一行。主列 `mean_reward` 是所有环境最近结束的最多 100 个回合的平均累计环境奖励，三个分任务列各自使用本任务的最近 100 个回合。各窗口同时记录回合数量。AMP 含风格奖励的统计可查 `training_reward.csv`。断点恢复会接上已提交的完整回合窗口，新进程重新开始采集回合。

检查一条结构的训练曲线时，在每个任务自己的尺度上看 reward 趋势，并结合终止次数。正式评估负责判定最终策略能否完成任务。

## 验证范围

已用CPU真实优化验证保存/恢复后的actor、critic及Adam下一步结果完全一致，并校验协调器随机数恢复；用三个真实CPU子进程运行实际IPC服务，完成“更新1→暂停→身份错误拒绝→显式恢复→更新2→六项后评估→完成后不重跑”。物理环境和评估测量使用合成数据，不能据此判断机器人能否走好。
