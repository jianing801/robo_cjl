## 保存与分组

每步在原生奖励计算后、自动重置之前采集，写入extras.log。现有原生日志器按rollout逐更新平均，并写TensorBoard及控制器保留的stdout.log。前缀为`Health/knee/型号/`及`Health/ankle/型号/`。分母只包含当前组真实存在的对应型号环境；未出现的型号不输出，不能当作零。

相同型号跨腿长、跨另一部位型号合并，属于条件汇总，不代表已经隔离型号因果。每个新场景创建新分组缓存，不复用旧场景。快照detach并clone，不被后续reset覆盖；不逐步转换为CPU标量，但新增GPU归约存在开销，尚未实测4096规模性能。

## 字段

| 字段 | 含义 |
|---|---|
| reward_per_step | 对应环境的总单步奖励均值（已含dt） |
| forward_velocity_mps | 重置前机体系前向速度，m/s |
| termination_fraction | 该步失败终止环境比例，不含超时 |
| reset_fraction | 该步所有重置环境比例，包含超时 |
| mean_abs_raw_action | 当前输入动作缓存的对应关节绝对值均值，未转为PD目标 |
| mean_abs_applied_nm | 对应关节实际扭矩绝对值均值，N·m |
| utilization_valid_mean | 只在有效可用力矩关节上计算的利用率均值 |
| over_80_fraction_valid | 有效关节利用率超过0.8的比例 |
| saturated_99_fraction_valid | 有效关节利用率不低于0.99的比例 |
| unavailable_fraction | 当前可用力矩不大于峰值1e−6的关节比例 |
| requested_excess_nm | 裁剪前请求超过动态可用力矩的量，含零能力区，N·m |
| soft_reward_per_step | 对应环境整个六关节软惩罚的单步贡献，不是只属于该膝/踝组的惩罚 |
| soft_share_abs_reward_budget | 对应环境软惩罚绝对值之和 / 全部加权奖励分项绝对值之和 |
| nonfinite_fraction | 输出、请求或动态上限中任一非有限的关节比例 |

扭矩、曲线上限、请求均为最后物理子步的配对值，不是控制周期平均或峰值。有效关节数为0时利用率统计返回0，此时必须同时看unavailable_fraction，不能解释为健康。非有限值不静默清洗；nonfinite_fraction提供提示。

RewardManager的_step_reward是加权奖励率，日志转换单步贡献只乘一次step_dt；不把贡献再加回奖励。占比采用绝对分项预算，避免正负奖励抵消使分母异常小；rollout记录是逐步占比的平均，不冒充整个rollout总量比。

## 解读与边界

优先同时查看速度、终止频率、饱和比例与请求超额：低奖励不能单独判失败；高利用率也可能是必要推进动作。奖励占比用于判断−4是否压过其他奖励，但不自动调权重、不自动停训。非有限值或频繁零能力区应进一步检查。

这里是按环境步数均衡的统计，不是“最近100个完成回合”的平均，避免短回合主导统计。并未实现遗忘指标或长期窗口告警。

45项CPU回归通过：型号分组、零能力掩码、禁用软约束、步长与奖励占比、不可变终态快照、新场景缓存隔离，以及实际奖励hook调用。训练代码身份随新增模块变化，不应拿旧run直接冒充同身份续训。
