# 保持服务器原安装版本的URDF导入

服务器报错证据：本地已安装isaacsim.asset.importer.urdf 2.4.30，但IsaacLab的UrdfConverter构造函数对Sim>=5.1主动请求2.4.31；远端仓库不可达，导入失败。动态惩罚和健康日志没有声明扩展版本。旧启动成功的完整配置尚未取得，不能声称其差异原因已完全还原。

本次只在独立Rough进程内增加受限适配，不修改Isaac Sim、IsaacLab、扩展清单、用户配置或安装包，也不伪造版本号：

1. 检查原生构造函数AST确为已审核的2.4.31版本锁及其余三步初始化逻辑；未知构造函数不替换。
2. 只对当前Python环境确实安装的2.4.30情况生效。读取原安装extension.toml，不改其内容。
3. 启用明确的本地2.4.30并核对实际加载路径。如果已有其他版本启用，则报错，拒绝自动切换。
4. Rough的转换器子类只跳过上述主动版本锁，保留相同URDF接口获取及AssetConverterBase初始化。转换、关节处理等其余方法全部继承原生实现。不使用任何2.4.31代码冒充2.4.30。
5. 每组保存importer_audit.json记录安装版本、启用ID、路径、是否适配。无本地清单或启用失败则停止，不自动下载兜底。

这保持了服务器原安装扩展，而不是证明两个扩展版本语义等价。现有几何及关节审计仍必须通过；不能跳过物理审核。

另外，环境初始化中途失败时，close再次报缺少event_manager不再覆盖原始异常。次级清理错误仍输出，原failure.json保留第一条根因。

源码身份已变化；不能直接恢复旧plan。可保留本次生成的6216P结构库，在全新训练输出目录从零启动，不加resume。不得删除失败输出。
