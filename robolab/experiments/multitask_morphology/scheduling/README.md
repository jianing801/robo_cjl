# 60结构 × 50组：离线均衡排表试验

本目录是可复现的 CPU 排表试验，**尚未修改三个专家的正式调度**，不加载 Isaac、URDF、参考动作或教师模型，不启动训练。使用正式配置中的3000种完整四元组生成同样的 design_id，与当前 `cycle_groups` 作对照。

## 方法与依据

采用“精确循环构造＋候选筛选＋模拟退火优化组顺序”。不是 CP-SAT 求解，也不是 SLHD 或 OCD 论文算法的直接复现。本次找到显式可行构造，因此没有向已验证的训练环境安装额外求解器。

设计思想参考：

- [Zhang等，2019，Optimal Sliced Latin Hypercube Designs with Slices of Arbitrary Run Sizes](https://arxiv.org/abs/1908.01976)：同时评价整体与各切片覆盖。本文没有把固定10档网格冒充连续拉丁超立方。
- [Google OR-Tools分配问题示例](https://developers.google.com/optimization/assignment/assignment_example)：把结构唯一归属、组容量及配额分成明确约束。该工具本次没有参与计算。

### 精确构造

30种电机组合随机分为6块，每块5种。每块分别为5种组合分配 `a`、`z` 两个0到4的排列。

对组索引 `(r,d)`，其中 `r=0..4`、`d=0..9`，每种电机组合选择两个腿长索引点：

```text
t = (r+a) mod 5
c = (t+d+z-a) mod 10
点1 = (t,c)
点2 = (t+5,(c+5) mod 10)
```

由此可直接验证：

1. 每组30种电机组合各2次，总计60种。
2. 每块的大腿索引覆盖0到9各一次；6块合计每档大腿各6次。
3. `c mod 5 = (r+d+z) mod 5`，同理每档小腿各6次。
4. 对任一电机组合，遍历50组时，每个大腿索引会配遍全部10档小腿，所以100种腿长搭配各出现一次；全部30组合共3000种不重不漏。

这也使每款膝电机每组12种、每款踝电机每组10种。以上只证明计数性质，不能推出每款电机在每组内的二维搭配已经最均匀。

### 搜索

每个种子生成64份满足硬计数的候选表，选择覆盖目标较好的初始表。然后模拟退火12000步，每步只交换两个完整组的顺序，不改变组内结构和任何硬计数。

优化对象为每款膝/踝电机对应的3×3腿长区域分布。对1、5、10组循环窗口计算：

```text
TV = 0.5 × sum(abs(实际区域占比 − 全库该电机区域占比))
目标 = 各窗口宽度的 [mean(TV²) + 0.25 × max(TV)²] 之和
```

分箱按实际物理范围等宽分为3区，目标比例从完整离散库统计，不强行设成每区1/3。温度从0.003几何下降至0.000001；接受概率为 `min(1, exp((旧分数−新分数)/温度))`，始终返回已见最佳表。数值、窗口和权重是显式工程设置，不是引用文献的最优参数，也没有全局最优证明。

## 2026-11-14结果

种子42、43、44，各64候选＋12000次退火，约13秒/种子。独立审计从导出的ID重新数结构、电机、腿长和窗口，不以生成器目标分数代替验收。7项测试通过，覆盖5个构造种子、完整唯一性、精确边际、可复现、重复拒绝及交换保持分组。

| 硬计数 | 当前算法，3种子范围 | 新构造 |
|---|---:|---:|
| 每个电机组合每组出现次数 | 0–8 | 恰好2 |
| 每档大腿每组出现次数 | 0–16 | 恰好6 |
| 每档小腿每组出现次数 | 0–14 | 恰好6 |
| 每轮结构唯一性/完整性 | 3000不重不漏 | 3000不重不漏 |

下表为3个种子分别算指标，再取均值；“最坏”是每个种子的最坏窗口/电机，再对3个值取平均，并非把3个种子混为一张表。

| 每款电机二维区域分布TV，越小越好 | 当前算法 | 新方案 | 降低 |
|---|---:|---:|---:|
| 单组平均 | 0.3526 | 0.3481 | 1.3% |
| 单组最坏值的种子均值 | 0.7533 | 0.5733 | 23.9% |
| 连续5组平均 | 0.1443 | 0.0818 | 43.3% |
| 连续5组最坏值的种子均值 | 0.3025 | 0.1533 | 49.3% |
| 连续10组平均 | 0.0955 | 0.0485 | 49.2% |
| 连续10组最坏值的种子均值 | 0.2132 | 0.0933 | 56.2% |

额外检查未参与搜索的窗口：2、7、20组，3个种子的平均二维TV都下降。具体独立审计见试验输出 `holdout_windows.json`。

不能说所有指标全面改善：种子42、44的单组平均二维TV略差于基线；退火只优化顺序，本身不能改善单组组成。3种子并不构成统计显著性证明。没有进行PPO对照，因此不能声称已经减少遗忘或提高步态。

## 使用

从仓库根目录，用原训练Python执行，输出目录必须是新目录：

```bash
python robolab/experiments/multitask_morphology/scheduling/experiment.py \
  --output /absolute/path/to/new_schedule_trial \
  --seeds 42,43,44 --candidates 64 --iterations 12000
```

输出：`grid.json`、每种子的完整 `schedule_seed_N.json/.csv`、逐组及最坏窗口 `audit_seed_N.json`，以及汇总 `summary.json`。这是四元组排表，不是伪造含真实URDF的训练bank。

如后续接入训练：使用现有正式bank逐项匹配所有四元组/ID；冻结排表及哈希进入实验身份；训练时不重新搜索；保留组顺序以保持窗口性质，并考虑跨轮边界。本次审计循环窗口，对同一冻结表重复使用时跨轮成立；若各轮另换排表，必须重新审计交界。组内设计顺序应另行打散，避免4096除以60产生的16个额外副本固定偏向同一批电机组合。不能用这份试验表静默改动旧run的续训调度。

正式配置、预算、物理与奖励均保持原样。此试验说明“更可审计、计数更均衡、连续窗口覆盖更好”的候选方案可行，尚不把候选表自动标记为已验证训练方案。
