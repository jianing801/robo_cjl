# 三任务专家代码自查与修复

范围：当前Rough/负重/AMP完整候选池、GP外推、23关节动态扭矩约束、原生缓存、换组及恢复入口。旧实验、已训练模型、冻结源码与软件环境版本没有修改。

## 发现并修复的问题

1. **缓存中断被误认为PPO已经启动。** 原入口只检查是否存在任意launch记录，资产转换同样会产生该记录，导致缓存阶段中断也无法resume。现在按实际脚本识别：仅发生缓存转换时允许继续准备缓存；存在PPO工作进程启动记录、未知或损坏记录时仍拒绝隐式从头开始。Rough/负重和AMP共用该判断。USER_PAUSED仍优先，未自动清除。
2. **缓存完整性只检查了主USD。** 实际碰撞几何通常位于引用的USD层，修改这些层不会改变主文件。现在缓存证明采用schema 2，记录完整资产目录的几何/材质/配置等非临时文件哈希，同时把URDF引用的原始网格哈希写入实验身份和缓存证明。物理启动只使用完整证明列出的资产，排除失败批次；仅复核当前组几何，避免每一组重读全部几何。旧缓存不删除，但缺少新完整证明时须重新准备，不能冒充完整校验结果。
3. **执行器继承标记可能漏掉限值导出。** 原标记挂在类上，子类重写_clip_effort仍可能继承“已经导出”的状态，导致没有实时可用扭矩。现在标记绑定到实际裁剪方法，重写方法会单独安装。正常裁剪结果保持不变。
4. **异常物理量可能被当作零惩罚。** 可用扭矩NaN等非法值可能落入无效限值屏蔽分支，掩盖异常。现在非有限扭矩/限值或非法峰值会产生非有限奖励，令训练按现有失败处理停止；不再伪装成零。正常有限输入的公式、−12权重和dt处理不变。有限且可用扭矩为零的情况仍保留此前约定的单独统计、排除比值惩罚，不擅自改动该奖励设计。
