# Rough与背包：仅共同结构的共享学生

用户已明确要求结构库只用两位教师的交集，旧并集方案已停止。共享库按
大腿长度、小腿长度、膝电机精确型号、踝电机精确型号四元组配对，不按名称近似、
电机系列名或独立design_id猜测。普通4340P和4340P-V1.1-48V不等同。

当前全交集是200种：10×10腿长搭配，膝RS04或DM-J10010L-2EC，踝RS06。
两个任务分别采集同样的200种，合计400个任务—结构条件，不能说成400种结构。
模型的已知结构编码也只使用这两个膝型号和一个踝型号（21维），输入宽1153。
两位教师仍使用原生22/24维输入和原权重，不改教师训练库。

共享库每行指向两任务各自真实的原资产。负重任务保留backpack_link和运行时负载，
因此“腿长与电机设计相同”不表示两份URDF字节相同。初始化0.3kg由实际采样负载替换，
不会把0.3kg重复叠加。学生不额外观察真实负载质量、根线速度或地形扫描。

这是方法和接口参考，不是本次Rough/背包已验证的结果。原RUN/STAIRS权重不直接移植。

编码来自本行真实资产。只输出23个原关节动作，不加tanh。任务与结构均衡BC，按完整
物理环境流留出，实际学生roll-in状态由原教师打标签的DAgger，再做配对闭环评估。

## 数据与状态

prepare.py绑定实际教师文件及SHA，创建独立shared_bank和v2计划。load_plan逐次核对
两个任务选择的结构四元组集合相同，非交集电机/结构拒绝；旧v1并集计划明确拒绝。
旧39个任务—结构条件的采样、BC及失败DAgger产物保留在工作区pilot_run，已停止并标记
USER_PAUSED，不能当作新的交集学生或跨任务配对成果。新实验不初始化旧并集学生。

rollout.py只做原教师推理/真实采样或学生闭环，两个任务各自原物理场景；教师和PPO
更新均为0。原动作和本体观测的100裁剪保持，避免把原生能处理的有限超界动作误判为
不可采样。记录原生动作裁剪率，低MSE/裁剪率不构成步态成功。资产复用仅允许精确
原生转换哈希，原资产不改写；冷USD导出偶发停滞仍需检查，不能冒称已解决。

fit.py仅训练一个MxT actor，critic未训练，不能冒充完整PPO恢复。pipeline.py顺序采样、
BC/DAgger及同种子配对评估，失败产物不覆盖，只有完整数据和有效退出才提交。
评估初始化在构造模型后重新设随机种子，并保存初态以供核对，防止学生构造消耗RNG
破坏配对。原生教师动作只作冻结标签，不把负奖励均值或动作MSE当作步态合格。

scope=all采集200种共同结构；scope=pilot仅从同一交集中选短/中/长对角网格×两膝共6种，
两任务均为这6种。scope=smoke只是两个共同结构的接口测试，不能冒充全库结果。

默认提供有界采样/BC参数，真实运行输出及教师模型不入Git，旧结果全部保留。

## 2026-10-30 失败诊断与对照

详见 `DIAGNOSIS_20261030.md`。第一版全交集学生闭环失败，不能把完成文件当作成功证明。
后续 epoch 默认按真实训练数据规模计算，日志记录实际更新次数与期望抽样遍数。

`fit.py --architecture mlp` 提供一个普通共享 MLP 对照：原生780维历史、2维任务标记、
21维已知结构参数进入同一个网络和23维动作输出层，没有分别路由两位教师。
它不使用350维图节点展开，不新增负载实测量、根速度或地形等特权输入。
该对照用于检验当前固定23关节的参数化结构是否适合直接沿用教师式MLP表示；
拟合误差降低也必须接受相同闭环测试。现有MxT检查点保持兼容。
